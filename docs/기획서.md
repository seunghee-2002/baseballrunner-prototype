# Baseball Action Runner — 기획서 (PvP 프로토타입)

현재 **LAN 1v1 PvP 프로토타입**에 구현된 규칙을 정리한 기획서다.
이 문서를 기준으로 회의 내용을 반영해 기획안을 확정해 나간다.

---

## 0. 문서 안내

* 규칙과 수치는 **현재 프로토타입 코드에서 옮겼다.** 문서와 코드가 다르면 코드가 기준이다.
* 규칙 아래의 **왜 이렇게?** 는 지금까지 결정된 근거다.
* 수치는 모두 튜닝 대상이다. 한곳에 모은 표는 [부록 A](#부록-a-수치-표)에 있다.

## 1. 게임 개요

> **타격으로 CHANCE를 얻고, 주루 회피로 세이프를 지켜내며, 3루타 CHANCE에서 피버로 홈런을 노리는 1v1 대전.**

| 항목 | 내용 |
| --- | --- |
| 장르 | 반응형 야구 액션 러너 |
| 플랫폼 | 모바일 세로 화면(9:16). 프로토타입은 웹 |
| 대전 | 1v1, 같은 네트워크(LAN), **1이닝**(1회 초 / 1회 말) |
| 공격자가 하는 일 | **맞춘다**(타격) + **피한다**(주루) |
| 수비자가 하는 일 | **던진다**(투구) + **기습한다**(수비 카드) |
| 소재 | 야구. 실제 경기 규칙은 재현하지 않는 **야구 소재 아케이드** |
| 시점 | 타격은 타자 뒤, 주루는 주자 뒤 **3인칭** |
| 개발 조건 | 약 3개월, 3명 |

### 핵심 흐름

```text
[수비] 2단계 투구 → [공격] 타격 판정 → CHANCE → 주루 (수비는 카드로 기습) → 세이프 / 아웃 / 피버 홈런
```

### 노리는 순간

* **공격**: 3B CHANCE를 얻고, 피하고 또 피하며 피버를 모아 **홈런을 노리는 순간**.
* **수비**: 타자의 손을 **읽고 카드로 기습**해, 미리 나간 손을 헛손질로 만드는 심리전.

## 2. 핵심 설계 원칙

| 원칙 | 뜻 |
| --- | --- |
| **타격 = 기회, 주루 = 확정** | 타격 순간 결과가 정해지지 않는다. 타격은 목표(CHANCE)를 주고, 주루가 **세이프냐 아웃이냐**를 가른다 |
| **CHANCE는 주루 중 변하지 않는다** | 주루를 잘해도 루타가 오르지 않는다. 더 높이 가는 길은 **3B CHANCE + 피버 = 홈런** 하나뿐이다 |
| **입력은 화면 4분할 하나** | 타격·회피·투구 모두 같은 네 칸을 쓴다. 예외는 피버 버튼과 수비 카드뿐이다 |
| **자유 이동 없음** | 주자는 자동으로 달리고, 조작은 회피 동작뿐이다 |
| **위는 반대쪽, 아래는 같은 쪽** | 공은 반대쪽으로 몸을 피하고, 태클은 같은 쪽 다리를 든다. **일부러 넣은 혼란 요소**다 |
| **충돌 직전이 최고 판정** | 일찍 누를수록 좋은 구조가 아니다. 눈에 보이는 충돌과 판정이 맞아야 손이 납득한다 |
| **실패 이유가 보여야 한다** | 틀리면 잘못 누른 쪽으로 실제로 피한 뒤 맞고, 정답을 글로 보여준다 |
| **좋은 랜덤만 쓴다** | 필드 장애물은 패턴 + 예산 + 가중 랜덤으로 만든다. 운은 상황을 정하고, 실력은 상황을 해결한다 |
| **겹침은 수비 카드로만 생긴다** | 필드 장애물끼리는 겹치지 않게 보정한다. 동시에 오는 위험은 수비자가 만든 것이다 |
| **기습은 알리지 않는다** | 카드 발동을 공격자에게 알리지 않는다 |
| **실패는 짧게** | 아웃 후 0.75초 뒤 결과로 넘어간다 |
| **장애물과 카드는 데이터** | 새 장애물·카드는 데이터 표에 한 줄을 더해 만든다 |

## 3. 매치 구조

### 3.1 한 판 흐름

```text
로비 → 방 입장(선착 2명) → 1회 초 → 공수 교대 → 1회 말 → 매치 결과
```

| 단계 | 내용 |
| --- | --- |
| 1회 초 | **먼저 접속한 사람이 공격**, 다른 사람이 수비. 공격자가 3아웃이 되면 끝난다 |
| 공수 교대 | 역할이 바뀐다. 수비 코스트와 손패가 초기화된다. 안내 3초 |
| 1회 말 | 3아웃까지 진행한다. **끝내기는 없다** |
| 매치 결과 | 득점 합계를 비교한다. **동점은 무승부** |

### 3.2 한 타석 흐름

| 단계 | 시간 | 내용 |
| --- | --- | --- |
| 투구 선택 | 최대 3초 | 수비자가 두 칸을 고른다 |
| 투구 | 약 0.8 ~ 1.3초 | 레벨과 구종에 따라 다르다 |
| 타격 결과 | 1.0초 | 판정을 보여준다. MISS면 아웃 연출 뒤 타석 종료 |
| CHANCE | 1.15초 | 목표 루타를 보여준다 |
| 주루 | 5.0 ~ 18.5초 | CHANCE만큼 구간을 달린다 |
| 타석 결과 | 2.5초 | 결과 화면을 보여준 뒤 자동으로 다음 타석 |

### 3.3 득점과 아웃

| 결과 | 1B | 2B | 3B | HR | 아웃 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 점수 | 100 | 200 | 350 | 600 | 0 |

* **주자를 베이스에 남기지 않는다.** 타석마다 루타 점수만 더한다.
* 아웃 3개가 되면 반 이닝이 끝난다.

### 3.4 방과 연결

* 방은 하나이고 **먼저 들어온 2명**만 들어간다. 세 번째 사람은 "방이 가득 찼습니다"를 본다.
* 한쪽이 나가면 남은 쪽에 "상대가 나갔습니다"를 띄우고 로비로 돌아간다.

## 4. 조작

화면을 네 칸으로 나누고, **칸을 터치하는 것이 기본 입력**이다.

|  | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| **위** | 좌상 | 우상 |
| **아래** | 좌하 | 우하 |

| 입력 | 공격자 | 수비자 |
| --- | --- | --- |
| 4분할 칸 | 투구 중: 스윙 / 주루 중: 회피 | 투구 코스 선택 |
| 피버 버튼 (상단 가운데) | 게이지가 가득 찼을 때만 나타나고 누르면 발동 | — |
| 손패 카드 (하단) | — | 누르면 즉시 발동 |

* 칸마다 따로 입력을 받는다. **두 손가락으로 두 칸을 동시에 눌러도 각각 판정된다.**
* PC 조작: 좌상 `Q` / 우상 `E` / 좌하 `A` / 우하 `D`, 피버 `SPACE`, 카드 `1`~`4`.

**왜 이렇게?**

* 버튼 네 개를 화면에 깔면 QTE 게임처럼 보인다. **화면 자체를 입력 영역**으로 쓴다.
* 타격·회피·투구가 같은 네 칸이라 손이 체계 하나만 익히면 된다.

## 5. 수비 ① 투구

수비자는 **두 칸을 차례로 골라** 공을 던진다. 첫 칸은 시작 칸, 두 번째 칸은 도착 칸이다.

| 선택 | 구종 | 궤적 | 속도 |
| --- | --- | --- | --- |
| 같은 칸 두 번 | **직구** | 그 칸으로 곧게 온다 | 기본 비행 시간의 0.78배 (빠름) |
| 서로 다른 칸 | **변화구** | 시작 칸으로 오다가 **비행 55% 지점부터 도착 칸으로 휜다** | 기본 비행 시간 |
| 3초 안에 못 고름 | 직구 | 무작위 칸 직구가 자동으로 나간다 | — |

* 궤적은 시작 칸 4 × 도착 칸 4 = **16가지**다.
* 첫 칸을 고르면 그 칸에 "시작" 표시가 뜨고, 남은 선택 시간이 보인다.
* 기본 비행 시간은 레벨마다 짧아진다 (Lv.1 1.30초 → Lv.4 0.98초, [10.3](#103-레벨)).

## 6. 공격 ① 타격

타격은 **타이밍(언제)** 과 **코스(어디)** 를 함께 맞춘다.

* **타이밍 링은 없다.** 공의 궤적과 속도를 눈으로 읽는다.
* **쳐야 할 칸은 공이 도착하는 칸**이다. 변화구는 휘기 전까지 시작 칸으로 오는 것처럼 보인다.
* 투구 한 번에 스윙은 한 번이다.

### 6.1 타이밍

오차는 공이 도착한 순간과 칸을 누른 순간의 차이다.

| 등급 | 오차 | CHANCE | 추가 효과 |
| --- | --- | --- | --- |
| **JUST** | 0.030초 이내 | 3B | 런 게이지 60으로 출발, 앞 두 구간 1.5배 가속 |
| **PERFECT** | 0.070초 이내 | 3B | 앞 두 구간 1.5배 가속 |
| **GREAT** | 0.140초 이내 | 2B | — |
| **GOOD** | 0.230초 이내 | 1B | — |

### 6.2 코스

| 누른 칸 (타이밍 0.230초 이내) | 결과 |
| --- | --- |
| 도착 칸 | 타이밍 등급 그대로 |
| 옆 칸 (같은 줄 또는 같은 열) | **빗맞은 1B.** 등급과 상관없고 가속도 없다. 그중 **12%는 LUCKY** |
| 대각선 반대 칸 | **MISS → 아웃** |

| 그 밖의 경우 | 결과 |
| --- | --- |
| 오차 0.230초 초과 | MISS → 아웃 ("너무 빨랐다" / "너무 늦었다") |
| 공이 도착하고 0.24초가 지나도록 스윙 없음 | MISS → 아웃 ("스윙하지 않았다") |

* **파울은 없다.**

### 6.3 LUCKY

빗맞은 타격 중 12%에서 나온다.

| 대상 | 효과 |
| --- | --- |
| 타자 | **1B 또는 2B CHANCE** (반반) |
| 수비자 | **코스트 -2** (0 아래로는 내려가지 않음), **주루 시작 후 2초 동안 카드 잠금** |

**왜 이렇게?**

* 타격은 **정확도와 타이밍**, 주루는 **반응 속도와 판단**. 두 파트가 서로 다른 실력을 요구한다.
* 타격으로 얻는 CHANCE는 최대 3B다. 홈런은 피버로만 나온다 (8장).

## 7. 공격 ② 주루

### 7.1 구간

* 주자는 **자동으로 달린다.** 조작은 회피뿐이다.
* **한 구간 = 베이스 하나.** CHANCE만큼 구간을 이어 달리고, **마지막 베이스를 밟으면 세이프**다.
* 구간 길이는 **시간으로 고정**한다.

| 구간 | 기본 | JUST / PERFECT 타격 |
| --- | ---: | ---: |
| 홈 → 1루 | 5.0초 | 3.3초 |
| 1루 → 2루 | 5.5초 | 3.7초 |
| 2루 → 3루 | 8.0초 | 8.0초 |

| CHANCE | 총 주루 시간 |
| --- | --- |
| 1B | 5.0초 |
| 2B | 10.5초 (가속 7.0초) |
| 3B | 18.5초 (가속 15.0초) |

* 구간 사이에서 멈추지 않는다. 베이스를 밟는 순간 날아오던 장애물은 **다음 구간으로 이어진다.**
* 마지막 베이스에 닿으면 남은 장애물은 사라진다.
* 최종 결과는 **실제로 밟은 베이스 수**다.

**왜 이렇게?**

* 자유롭게 움직이게 하면 야구가 아니라 닷지 게임이 된다. **조작은 쉽게, 판단은 순간적으로.**
* 레벨은 구간 길이가 아니라 **장애물 밀도만** 올린다 ([10.3](#103-레벨)).

### 7.2 장애물과 정답

| 장애물 | 나오는 곳 | 오는 곳 | 노리는 곳 |
| --- | --- | --- | --- |
| **공** | 필드, 수비 카드 | 좌상 / 우상 | 상체 |
| **관객 난입** | 필드 (무작위) | 좌상 / 우상 | 상체 |
| **수비수 태클** | 필드, 수비 카드 | 좌하 / 우하 | 다리 |

| 위험 위치 | 누를 칸 | 캐릭터 동작 | 규칙 |
| --- | --- | --- | --- |
| 좌상 (공·관객) | **우상** | 오른쪽으로 상체를 피한다 | 반대쪽 |
| 우상 (공·관객) | **좌상** | 왼쪽으로 상체를 피한다 | 반대쪽 |
| 좌하 (태클) | **좌하** | 왼쪽 다리를 들어 넘긴다 | 같은 쪽 |
| 우하 (태클) | **우하** | 오른쪽 다리를 들어 넘긴다 | 같은 쪽 |

* 누른 칸의 의미는 항상 **"그 방향으로 몸을 움직인다"** 로 같다.
* 장애물은 멀리서 작게 나타나 커지며 다가온다. 접근은 **거리값 하나**(100 → 0 = 충돌)로 계산한다.

**왜 이렇게?**

* 3레인은 레인만 보고 움직이면 돼서 너무 쉽다. 이 방식은 **위험 위치 + 위험 종류 + 맞는 동작**을 함께 판단해야 한다.
* 위와 아래의 규칙이 다른 것은 **일부러 넣은 혼란 요소**다.

### 7.3 회피 판정

* **유효 창**: 충돌까지 **0.45초** 남은 순간부터 입력을 받는다.
* **누르는 순간 판정**하고, 누른 칸마다 따로 판정한다.

| 판정 | 조건 | 런 게이지 | 피버 | 수비 코스트 |
| --- | --- | --- | --- | --- |
| **PERFECT** | 유효 창 안에서 정답 칸, 충돌 **0.20초 이내** | +25 × 연속 배율 | +10 × 연속 배율 | +1 |
| **NICE** | 유효 창 안에서 정답 칸, 그보다 일찍 | +15 × 연속 배율 | +5 × 연속 배율 | +1 |
| **WRONG** | 유효 창 안에 장애물이 있는데 정답이 아닌 칸 | **-35**, 연속 끊김 | — | — |
| **TOO LATE** | 끝까지 누르지 않고 충돌 | **-45**, 연속 끊김 | — | — |
| **헛회피** | 유효 창 안에 장애물이 하나도 없는데 누름 | **0.35초 경직** (게이지·연속은 유지) | — | — |

* 판정 대상: 유효 창 안에서 누른 칸이 정답인 장애물 중 **가장 가까운 것**. 정답인 것이 없으면 가장 가까운 장애물이 WRONG이다.
* **연속 배율** = 1 + (직전까지 연속 성공 수 × 0.1). 최대 1.5배 (6번째 연속 성공부터).
* **관객 난입**을 피하면 연속 배율 없이 **게이지 +40, 피버 +50**을 받는다. 수비 코스트는 차지 않는다.
* 위험 두 개가 동시에 오면 **두 칸을 같이 누르면** 된다.
* 위험이 유효 창에 들어오면 **위험이 있는 칸**(정답 칸이 아님)이 잠깐 번쩍인다.

**왜 이렇게?**

* **충돌 직전이 최고 판정**이어야 눈에 보이는 충돌 순간과 판정이 맞는다.
* 무반응(TOO LATE)이 오답(WRONG)보다 무겁다. **틀리더라도 반응하는 편이 낫다.**
* 아무 때나 눌러 두는 입력은 헛회피 경직으로 손해를 본다.

### 7.4 런 게이지

* **런 게이지는 체력이다.** 시작 50 (JUST 60), 최대 100.
* **0 이하가 되면 즉시 아웃.**
* 게이지와 연속 기록은 한 타석 안에서 구간이 바뀌어도 이어진다.
* 게이지가 CHANCE를 올리거나 내리지 않는다.

### 7.5 아웃

| 아웃 | 조건 | 화면 문구 |
| --- | --- | --- |
| 타격 실패 | 타격 MISS | 타격 실패 |
| 게이지 고갈 | 런 게이지 0 이하 | 런 게이지가 바닥났다 |
| 무반응 2회 | **한 구간에서 TOO LATE 2회** (게이지가 남아 있어도) | 한 구간에서 두 번 반응하지 못했다 |
| 구간 성공 0 | **한 구간에서 하나도 못 피하고** 베이스에 닿음. 피버 무적을 쓴 구간은 예외 | 이 구간에서 하나도 피하지 못했다 |

* 아웃되면 0.75초 뒤 결과로 넘어간다.

**왜 이렇게?**

* "구간 성공 0" 아웃은 **공짜로 베이스를 밟는 것**을 막는다. 대신 필드 장애물은 구간마다 최소 하나를 보장한다 ([10.2](#102-안전-보정)).

## 8. 공격 ③ 피버·홈런

* 피버 게이지는 **타석마다 0에서 시작**하고, 최대 100이다. 회피에 성공하면 찬다 ([7.3](#73-회피-판정)).
* 가득 차면 **상단 가운데에 FEVER 버튼**이 뜬다 (PC `SPACE`). 주루 중이고 무적이 아닐 때만 누를 수 있다.

| 발동 시 CHANCE | 효과 |
| --- | --- |
| **3B CHANCE** | **홈런 직행.** 남은 장애물이 모두 사라지고, 남은 베이스를 **2.6초 동안 무적 질주**해 홈에 들어온다 (600점) |
| **1B · 2B CHANCE** | **방어 발동.** **2.5초 무적** + **런 게이지 +30** + 베이스 진행 1.5배 |

* 3B CHANCE 주루에서는 **어느 구간에서 발동하든 홈런**이다.
* 일반 주루로는 홈런이 나오지 않는다.
* 방어 발동 중에는 회피 입력을 받지 않는다. 유효 창에 들어온 장애물은 자동으로 통과하며, 보상·감점·수비 코스트가 없다.

**왜 이렇게?**

* CHANCE가 주루 중에 오르지 않으므로, **욕심이 생기는 지점을 "3B에서 피버를 모아 홈런"** 으로 옮겼다.
* 피버 충전량(PERFECT +10 / NICE +5)의 근거: 봇 대 봇 40경기에서 +20 / +12는 세이프의 40%가 홈런이었고, +10 / +5는 약 9%였다.

## 9. 수비 ② 코스트·카드

### 9.1 코스트

* 반 이닝 시작 시 **3**, 최대 **10**. 반 이닝 안에서는 타석이 바뀌어도 유지된다.
* **시간으로 차지 않는다.** 타자가 필드·카드 장애물을 **피할 때마다 +1**.
  관객 난입 회피와 피버 무적 통과는 코스트를 주지 않는다.
* 타자가 LUCKY를 치면 -2.

### 9.2 덱과 손패

* 덱은 **8장** (C01~C08 한 장씩), **손패는 4장**. 반 이닝 시작 시 섞어서 4장을 받는다.
* **카드 위치는 손패에 들어올 때 무작위로 정해져 카드에 표시된다.** (C07·C08은 위치 없음)
* 카드를 누르면 **즉시 발동**하고 코스트가 빠진다.
* 쓴 카드는 덱으로 돌아간다. 보충은 **손패에 있는 카드와 방금 쓴 카드를 뺀 나머지**에서 무작위로 뽑는다.
* 카드에는 코스트, 위치 화살표, 이름, 종류, 단축키, 못 쓰는 이유가 표시된다.

### 9.3 카드 8종

| ID | 이름 | 종류 | 코스트 | 위치 | 효과 |
| --- | --- | --- | ---: | --- | --- |
| C01 | 고속 직격 공 | 상단 | 1 | 위 한 칸 | **1.35배 빠른** 공 |
| C02 | 슬라이딩 태클 | 하단 | 1 | 아래 한 칸 | **1.35배 빠른** 태클 |
| C03 | 대각 굴절 공 | 상단 | 2 | 위 한 칸 | 충돌 0.55초 전 **반대편 위 칸**으로 옮겨간다 (좌상 ↔ 우상) |
| C04 | 점핑 태클 | 하단 | 2 | 아래 한 칸 | 충돌 0.55초 전 **반대편 아래 칸**으로 옮겨간다 (좌하 ↔ 우하) |
| C05 | 시차 2연타 공 | 상단 | 3 | 위 한 칸 | 같은 칸으로 공 두 개, **충돌 0.20초 차이** |
| C06 | 상하 샌드위치 | 복합 | 3 | 위 한 칸 + 아래 한 칸 | 공과 태클, **충돌 0.15초 차이** |
| C07 | 변박 체인지업 | 교란 | 2 | — | 다가오는 가장 가까운 공을 **충돌 0.5초 전에 0.4배 속도로 감속** |
| C08 | 시야 흙먼지 | 교란 | 2 | — | **1초 동안 공격자 화면 가운데를 가린다** |

* 장애물 카드는 발동 즉시 먼 거리에서 출발한다. 레벨 속도와 바람이 똑같이 적용된다.
* C03·C04의 칸 이동과 C07의 감속은 **유효 창이 열리기 직전**에 일어난다. 미리 나간 손은 헛회피가 된다.
* 카드 장애물도 필드 장애물과 똑같이 피하면 타자에게 게이지·피버를, 수비자에게 코스트 +1을 준다.

### 9.4 카드를 못 쓰는 경우

| 카드 표시 | 조건 |
| --- | --- |
| (흐리게) | 주루 중이 아님 (투구·타격·홈런 질주 중) |
| 잠금 | LUCKY 후 주루 시작 2초 동안 |
| 코스트 부족 | 코스트가 모자람 |
| 다가오는 공 없음 | C07: 감속 지점 전의 공이 없음 |
| 베이스 임박 | 장애물 카드: **마지막 베이스에 닿기 전에 부딪힐 수 없음** |

### 9.5 기습은 알리지 않는다

* 카드를 발동해도 **공격자 화면에는 아무 알림이 없다.** 수비자 화면에만 "○○ 발동" 문구가 뜬다.
* 흙먼지(C08)는 공격자 화면에만 보인다.
* 필드 장애물끼리는 겹치지 않게 보정하지만, **카드 장애물의 겹침은 보정하지 않는다.**

**왜 이렇게?**

* 카드는 **"읽고 반응하는" 심리전**을 만드는 장치다. 예고가 있으면 기습이 되지 않는다.
* 코스트가 타자의 회피 성공으로 차므로, **타자가 잘할수록 수비자의 반격 수단이 늘어난다.**

## 10. 필드 장애물·난이도

### 10.1 생성 방식 — 패턴 + 예산 + 가중 랜덤

필드 장애물은 **완전 랜덤으로 만들지 않는다.**

1. **패턴**: 장애물 몇 개를 순서대로 묶은 것. 난이도 점수가 붙어 있다 (쉬움 1 / 보통 2 / 어려움 3).
2. **구간 예산**: 홈→1루 **1점** / 1루→2루 **2점** / 2루→3루 **3점**.
3. **가중 랜덤**: 예산 안에서 패턴을 뽑는다. 같은 패턴은 연달아 뽑지 않는다.
   **레벨이 높을수록, 뒤 구간일수록** 어려운 패턴이 뽑힐 확률이 커진다.

| ID | 점수 | 등장 레벨 | 순서 |
| --- | ---: | --- | --- |
| E1 | 1 | Lv.1 | 공 좌상 |
| E2 | 1 | Lv.1 | 공 우상 |
| E3 | 1 | Lv.2 | 태클 좌하 |
| E4 | 1 | Lv.2 | 태클 우하 |
| N1 | 2 | Lv.1 | 공 좌상 → 공 우상 |
| N2 | 2 | Lv.1 | 공 우상 → 공 좌상 |
| N3 | 2 | Lv.2 | 공 좌상 → 태클 우하 |
| N4 | 2 | Lv.2 | 태클 좌하 → 공 우상 |
| N5 | 2 | Lv.2 | 태클 우하 → 태클 좌하 |
| H1 | 3 | Lv.2 | 공 좌상 → 공 우상 → 태클 좌하 |
| H2 | 3 | Lv.2 | 태클 우하 → 공 좌상 → 공 우상 |
| H3 | 3 | Lv.3 | 공 우상 → 태클 좌하 → 공 좌상 → 태클 우하 |
| H4 | 3 | Lv.3 | 공 좌상 → 공 좌상 → 공 우상 (같은 방향 연속으로 손이 먼저 나가게 한다) |
| H5 | 3 | Lv.4 | 태클 좌하 → 태클 우하 → 공 좌상 → 공 우상 |

### 10.2 안전 보정

* 구간이 시작되고 **0.55초 뒤**에 첫 장애물이 출발한다.
* 필드 장애물끼리 **유효 창이 겹치지 않게** 간격을 벌린다 (여유 0.12초).
* 베이스 도착 0.25초 전까지 부딪힐 수 없는 장애물은 뺀다. **단, 구간마다 최소 하나는 남긴다.**

**왜 이렇게?**

* 화면 밖에서 갑자기 등장하거나, 너무 짧은 대응 시간, 필드가 스스로 만든 동시 위험은 **운이 아니라 억까**로 느껴진다.

### 10.3 레벨

* 레벨은 **타자별 타석 수**로 오른다.

| 타석 | 1~2 | 3~4 | 5~7 | 8~ |
| --- | --- | --- | --- | --- |
| 레벨 | Lv.1 | Lv.2 | Lv.3 | Lv.4 |

* 레벨은 **구간 길이가 아니라 밀도만** 올린다.

| 레벨 | 장애물 속도 | 장애물 간격 | 투구 비행 시간 (변화구 / 직구) |
| --- | ---: | ---: | --- |
| Lv.1 | ×1.00 | ×1.30 | 1.30초 / 1.01초 |
| Lv.2 | ×1.10 | ×1.10 | 1.20초 / 0.94초 |
| Lv.3 | ×1.22 | ×0.95 | 1.08초 / 0.84초 |
| Lv.4 | ×1.35 | ×0.85 | 0.98초 / 0.76초 |

* 필드 공이 나타나서 충돌까지 약 1.9초(Lv.1) → 약 1.4초(Lv.4). 태클은 약 2.2초 → 약 1.6초. (바람 제외)
* **Lv.1은 학습 단계**다.
  * 필드 장애물은 **공만** 나온다 (수비 카드로는 태클이 나올 수 있다).
  * 공격자 화면에 **정답 칸 화살표**를 보여준다. 타격은 도착 칸이 확정되는 순간부터, 주루는 유효 창에 들어온 장애물마다.

### 10.4 바람

* 필드·카드 장애물마다 속도가 **±5~10%** 무작위로 달라진다.

### 10.5 관객 난입

* 구간마다 **7%** 확률로 관객이 위 좌/우에서 뛰어든다. 정답은 공과 같다 (반대쪽 위).
* 필드 장애물 충돌 시각과 **0.6초 이상** 떨어뜨린다.
* 피하면 **피버 +50, 게이지 +40**. 실패 감점은 다른 장애물과 같다.

## 12. 연습 모드

* 서버 없이 혼자 한다. **역할을 고르고 봇과 대결**한다.
  * 연습 · 공격 = 봇 수비 상대로 공격
  * 연습 · 수비 = 봇 타자 상대로 수비
* **반 이닝(3아웃)** 만 한다. 끝나면 "내 점수" 또는 "내준 점수"를 보여주고 다시 / 로비로를 고른다.
* 봇은 정교한 AI가 아니라 **확률로만 움직인다.**

| 봇 | 행동 |
| --- | --- |
| 봇 수비 | 타석 시작 0.8~2.2초 뒤 투구, 직구 40%. 주루 중 0.5초마다 35% 확률로, 쓸 수 있는 카드 중 하나를 무작위로 쓴다 |
| 봇 타자 · 타격 | 도착 칸 70% / 옆 칸 20% / 대각선 10%. 타이밍 오차 표준편차 0.09초. 5%는 스윙하지 않는다 |
| 봇 타자 · 회피 | 정답 85% / 오답 8% / 무반응 7%. C03·C04 칸 이동에 30%, C07 감속에 50% 속는다 |
| 봇 타자 · 피버 | 가득 차면 3B CHANCE이거나 게이지가 40 미만일 때 발동 |

## 부록 B. 네트워크 구조·패킷

### 실행

* PC에서 `node server.js` 를 실행하고, 출력된 `http://주소:8080` 으로 **같은 네트워크의 두 기기**가 접속해 PvP를 누른다.
* 3D 라이브러리를 인터넷에서 불러오므로 모든 기기에 인터넷 연결이 필요하다.
* 연습 모드는 서버 없이 `index.html` 을 직접 열어도 된다.

### 구조 — 판정은 공격자 한 곳에서만

```text
 수비자 ──PITCH_SELECT / CARD_PLAY──▶  서버 ──▶ 공격자 (모든 판정)
 수비자 ◀──RUN_STATE(초당 20회) 등───  서버 ◀── 공격자
```

| 역할 | 하는 일 |
| --- | --- |
| 공격자 | 타격·주루·회피·피버·아웃을 **모두 판정**하고, 장면 상태(스냅숏)를 초당 20회 보낸다 |
| 수비자 | 받은 스냅숏으로 **같은 장면을 그린다.** 받은 뒤 흐른 시간만큼(최대 0.25초) 앞으로 밀어 그린다 |
| 서버 | 패킷 중계, 아웃·점수·이닝·승패만 관리한다 |

* 연출은 공격자·수비자 모두 **스냅숏의 이벤트 목록**에서 만든다. 두 화면이 같은 연출 경로를 쓴다.
* 타석마다 번호(`seq`)를 붙여, 이전 타석의 늦은 패킷은 버린다.

### 패킷

형식: `{ t: 패킷ID, p: 내용 }` JSON

| 패킷 | 보냄 → 받음 | 주요 내용 | 설명 |
| --- | --- | --- | --- |
| `WAITING` | 서버 → 접속자 | `you` | 상대를 기다리는 중 |
| `ROOM_FULL` | 서버 → 접속자 | — | 방이 가득 참 |
| `MATCH_START` | 서버 → 둘 다 | `role`, `you`, `half`, `halves`, `scores` | 역할 부여, 매치 시작 |
| `AT_BAT_START` | 서버 → 둘 다 | `seq`, `atBat`, `level`, `outs`, `scores`, `half`, `attacker` | 타석 시작 |
| `PITCH_SELECT` | 수비 → 공격 | `seq`, `startPos`, `endPos` (1~4), `timeout` | 2단계 투구 |
| `BAT_RESULT` | 공격 → 수비 | `seq`, `result`, `chance`, `zone`, `mishit` | 타격 판정 (LUCKY면 수비 핸디캡) |
| `RUN_STATE` | 공격 → 수비 | 스냅숏 전체 | 초당 20회, 수비 화면용 |
| `CARD_PLAY` | 수비 → 공격 | `seq`, `cardId`, `zones`, `spawnTime` | 카드 발동 |
| `DODGE_SUCCESS` | 공격 → 수비 | `seq`, `costGained` | 회피 성공, 수비 코스트 충전 |
| `FEVER_ACTIVATE` | 공격 → 수비 | `seq`, `isHomeRun` | 피버 발동 |
| `OUT_OCCURRED` | 공격 → 서버 → 수비 | `seq`, `currentOuts`, `reason`, 타석 기록, `scores` | 아웃 |
| `SAFE` | 공격 → 서버 → 수비 | `seq`, `bases`, `result`, 타석 기록, `gained`, `scores` | 세이프 |
| `INNING_CHANGE` | 서버 → 둘 다 | `scores`, `role`(받는 사람 기준), `half` | 공수 교대 |
| `GAME_OVER` | 서버 → 둘 다 | `winner` (무승부 `null`), `scores` | 매치 종료 |
| `OPPONENT_LEFT` | 서버 → 남은 사람 | — | 상대가 나감 |

## 부록 C. PvE → PvP 변경점

이전 싱글플레이(PvE) 기획에서 바뀐 것이다. 이전 버전 코드는 `legacy/` 에 남아 있다.

| 항목 | 이전 (PvE) | 현재 (PvP) | 비고 |
| --- | --- | --- | --- |
| 플레이 형태 | 혼자, 아웃 3개까지 점수 | **1v1, 1이닝 공수 교대** | |
| 투구 | 자동 | **수비자가 2단계로 코스·구종 선택** | |
| 타격 표시 | 도착 칸에 타이밍 링 | **링 없음**, 궤적을 읽는다 | |
| 쳐야 할 칸 | 공이 들어오는 칸 | **변화구의 도착 칸** | |
| 대각선 반대 칸 | 파울 (타석당 2번까지) | **MISS → 아웃**. 파울 폐지 | |
| 옆 칸 | 빗맞은 1B | 빗맞은 1B, 그중 **12% LUCKY** | |
| CHANCE | 주루 중 게이지 100에 오르고 0 아래에서 떨어짐 | **주루 중 변하지 않음** | 결정 사항 |

| 3B 이후 게이지 절반 | 있음 | 없음 | |
| 홈런 | 주루로 CHANCE를 HR까지 올림 | **3B CHANCE + 피버 발동으로만** | |
| 피버 | 없음 | **있음** (방어 발동 / 홈런 직행) | |
| 장애물 출처 | 필드만 | 필드 + **수비 카드** + **관객 난입** | |
| 동시 위험 | "한 번에 하나씩" 원칙 | 필드끼리는 겹치지 않음. **카드로 생긴 겹침은 두 칸 동시 입력** | 결정 사항 |
| 회피 입력 | 가까워지기 전 입력은 무시, 장애물당 입력 1회 | **누르는 즉시 판정**, 창 밖 입력은 **헛회피 경직** | |
| 아웃 | 구간 성공 0 | **4종** (타격 MISS / 게이지 고갈 / 무반응 2회 / 구간 성공 0) | |
| 바람 | 없음 | 장애물 속도 ±5~10% | |
| 구간 시간 | — | 5.0 / 5.5 / 8.0초 고정, JUST·PERFECT 앞 두 구간 가속 | |

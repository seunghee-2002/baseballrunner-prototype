## 1. 게임 개요

> **타격으로 생명을 얻고, 주루 회피로 생명을 지키며, 생명이 남아 있는 한 홈까지 달리는 1v1 대전.**

| 항목 | 내용 |
| --- | --- |
| 장르 | 반응형 야구 액션 러너 |
| 플랫폼 | 모바일 세로 화면(9:16). **[변경] Unity 3D** |
| 대전 | 1v1, **[변경] 3이닝** (초 / 말), 플레이타임 목표 **5분** |
| 공격자가 하는 일 | **맞춘다**(타격) + **피한다**(주루) |
| 수비자가 하는 일 | **던진다**(투구 카드) + **기습한다**(장애물 카드) |
| 소재 | 야구 소재 아케이드. 실제 경기 규칙은 재현하지 않는다 |
| 시점 | **[변경] 공격자와 수비자가 다른 뷰**를 본다 ([10장](#10-화면뷰)) |

### 핵심 흐름

```text
[수비] 투구 카드 + 칸 탭 → [공격] 타격 → 생명 획득 → 주루 (수비는 장애물 카드로 기습)
      → 생명이 남은 채 홈 도착 = 홈런 / 생명 소진 = 거기까지
```

### 노리는 순간

* **공격**: 빗맞은 타구라도 **하나도 안 맞으면 홈런**이다. 생명 하나를 쥐고 3루를 도는 순간.
* **수비**: 타자의 손을 **읽고 카드로 기습**해 생명을 깎는 심리전.

## 2. 핵심 설계 원칙

| 원칙 | 뜻 |
| --- | --- |
| **타격 = 생명, 주루 = 거리** | **[변경]** 타격은 목표 루타가 아니라 **생명 수**를 준다. 주루는 생명이 다할 때까지 이어지고, 어디까지 갔느냐가 점수다 |
| **상한 없는 주루** | **[변경]** 어떤 타구든 이론상 홈런이 가능하다. 피버·CHANCE는 없다 |
| **판정은 한곳에서** | 타격·회피·아웃은 공격자 기기에서 판정한다. Unity로 가도 같다 ([부록 B](#부록-b-unity-통신-구조)) |
| **4분할 = 방향 입력** | **[변경]** 네 칸은 "어느 방향" 을 정하는 입력이다. 회피 방향, 투구 시작 칸, 스윙 코스 |
| **자유 이동 없음** | 주자는 자동으로 달리고, 조작은 회피뿐이다 |
| **위는 반대쪽, 아래는 같은 쪽** | 공은 반대쪽으로 상체를 피하고, 태클은 같은 쪽 다리를 든다. 일부러 넣은 혼란 요소 |
| **충돌 직전이 최고 판정** | 일찍 누를수록 좋은 구조가 아니다 |
| **실패 이유가 보여야 한다** | 틀리면 잘못 누른 쪽으로 피한 뒤 맞고, 정답을 글로 보여준다 |
| **좋은 랜덤만 쓴다** | 필드 장애물은 패턴 + 예산 + 가중 랜덤 |
| **겹침은 다중 카드로만 생긴다** | **[변경]** 카드에 전역 쿨다운이 있어 카드끼리도 겹치지 않는다. 동시 위험은 C05·C06처럼 한 장이 둘을 내는 카드에서만 나온다 |
| **수비자는 먼저 보고, 공격자는 늦게 본다** | **[변경]** 수비자는 필드 장애물을 약 1초 먼저 본다. 카드 발동은 공격자에게 알리지 않는다 |
| **플레이타임이 닫혀 있다** | **[변경]** 반 이닝은 공격 횟수로 끝난다. 실력자도 게임을 무한히 끌 수 없다 |
| **실패는 짧게** | 아웃 후 0.75초 뒤 결과로 넘어간다 |
| **장애물과 카드는 데이터** | 새 장애물·카드는 데이터 표에 한 줄을 더해 만든다 |

## 3. 매치 구조

### 3.1 한 판 흐름 [변경]

```text
로비 → 방 입장 → 1회 초 → 1회 말 → (핸디캡 판정) → 2회 초 → … → 3회 말 → 매치 결과
```

| 항목 | 내용 |
| --- | --- |
| 이닝 수 | **3이닝** [가안]. 실제 플레이타임을 측정한 뒤 조정한다 |
| 반 이닝 종료 | **공격 횟수 3회를 다 쓰면** 끝난다. 그 전에 **2아웃**이 나오면 조기 종료 |
| 공수 교대 | 역할이 바뀐다. 수비 코스트·장애물 손패·투구 손패가 초기화된다 |
| 매치 결과 | 득점 합계 비교. **동점은 무승부** |

* "공격 횟수" 는 타석 수다. 파울·볼로 다시 던지는 것은 같은 타석이므로 횟수를 쓰지 않는다.
* 2아웃은 종료 조건이 아니라 **조기 종료 조건**이다.

### 3.2 핸디캡 [변경]

* 이닝이 끝날 때 점수를 비교해, **뒤진 쪽의 다음 이닝 공격 횟수를 +1** 한다.
* 발동 기준: **점수 차가 공격 찬스 1회로 뒤집기 힘들 때.**
  기준값은 새 규칙으로 **1이닝 평균 점수를 측정한 뒤** 확정한다 [미정].
* 마지막 이닝 말에는 다음 이닝이 없으므로 핸디캡이 없다.

**왜 이렇게?**

* 뒤진 쪽에 타격 판정을 후하게 주는 것은 실력 측정을 흐리고, 들키면 고무줄로 느껴진다.
* 앞선 쪽의 수비 코스트를 깎으면 앞선 쪽이 구경만 하게 된다.
* 공격 횟수 +1은 **양쪽이 게임을 온전히 한 타석 더 하는** 방법이다.

### 3.3 한 타석 흐름 [변경]

| 단계 | 시간 | 내용 |
| --- | --- | --- |
| 투구 선택 | 최대 3초 | 수비자가 **투구 카드 + 칸**을 고른다 |
| 투구 | 약 0.8 ~ 1.3초 | 카드와 칸에 따라 궤적이 정해진다 |
| 타격 결과 | 1.0초 | 안타면 생명 표시 → 주루. 스트라이크·볼이면 카운트를 올리고 **다시 투구 선택으로** |
| 주루 | 생명이 다하거나 홈까지 | 구간 4개 (홈→1루→2루→3루→홈) |
| 타석 결과 | 2.5초 → [가안] 1.5초 | 결과 화면 뒤 자동으로 다음 타석 |

* 한 타석에 투구는 최대 3번이다 (스트라이크 1 + 볼 1 + 마지막).

### 3.4 득점과 아웃 [변경]

| 결과 | 1루 | 2루 | 3루 | 홈런 | 아웃 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 점수 | **50** | **150** | **400** | **1000** | 0 |

* 점수는 **실제로 밟은 마지막 베이스**로 정한다. 주자를 베이스에 남기지 않는다.
* 2볼 출루는 **2루 (150점)** 로 처리하고 주루는 하지 않는다.

### 3.5 플레이타임 [가안]

한 타석 최대 시간 (투구 3회 + 주루 홈까지 + 결과) 을 기준으로 잡은 상한이다. 구간 시간은 [7.1](#71-구간)의 단축안 기준.

| 구성 | 시간 |
| --- | --- |
| 투구 3회 (선택 + 비행 + 결과) | 약 15초 |
| 주루 홈까지 | 약 20초 |
| 타석 결과 | 1.5초 |
| 한 타석 최대 | 약 37초 |
| 반 이닝 최대 (3타석) | 약 1분 50초 |
| 3이닝 최대 | 약 11분 |

* 실제로는 아웃·짧은 주루가 섞여 훨씬 짧다. **봇 대 봇으로 평균을 측정**한 뒤 이닝 수·구간 시간을 조정한다.

|  | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| **위** | 좌상 | 우상 |
| **아래** | 좌하 | 우하 |

## 5. 수비 ① 투구 카드 [변경]

투구는 **카드가 공의 움직임을, 칸이 시작 위치를** 정한다.

### 5.1 입력

1. 투구 손패에서 카드를 한 장 고른다.
2. 4분할 중 한 칸을 탭한다 → **시작 칸**.
3. 공은 시작 칸에서 카드의 이동 방향대로 움직여 **도착 칸**에 온다.
   * 이동 방향이 없는 카드(직구)는 시작 칸 = 도착 칸.
   * 이동한 결과가 **네 칸 밖**이면 **볼**이다.
4. 3초 안에 못 고르면 **무작위 칸 직구**가 나간다.

예: "좌→우 슬라이더" 카드 + 좌상 탭 = 좌상에서 우상으로 휘는 변화구. 같은 카드 + 우상 탭 = 우상에서 화면 밖으로 빠지는 **볼**.

### 5.2 손패와 덱

* 투구 풀 **6장**, 손패 **3장**. 장애물 카드와는 **다른 덱**이다.
* 쓴 카드는 덱으로 돌아가고, 손패에 있는 카드와 방금 쓴 카드를 뺀 나머지에서 보충한다 (장애물 카드와 같은 규칙).
* **이닝마다** 전체를 다시 섞어 3장을 받는다.

### 5.3 투구 카드 6종 [가안]

카드마다 **난이도**가 있고, 난이도가 낮을수록 그 타석에 **수비 코스트를 더 많이** 준다 ([8.1](#81-코스트)).

| ID | 이름 | 이동 | 속도 | 난이도 | 타석 시작 코스트 |
| --- | --- | --- | --- | --- | ---: |
| P1 | 직구 | 없음 | 빠름 (0.78배) | 쉬움 | +3 |
| P2 | 좌→우 슬라이더 | 오른쪽 한 칸 | 보통 | 보통 | +2 |
| P3 | 우→좌 슬라이더 | 왼쪽 한 칸 | 보통 | 보통 | +2 |
| P4 | 낙차 포크 | 아래 한 칸 | 보통 | 보통 | +2 |
| P5 | 라이징 | 위 한 칸 | 보통 | 보통 | +2 |
| P6 | 대각 커브 | 대각선 한 칸 | 느림 | 어려움 | +1 |

* 볼이 되는 조합: P2 + 오른쪽 열, P3 + 왼쪽 열, P4 + 아랫줄, P5 + 윗줄, P6 + 대각선 방향에 따라 [미정].
* 변화구는 비행 55% 지점부터 휜다. 직구는 기본 비행 시간의 0.78배.
* 카드 이름·구성·난이도·코스트 값은 전부 조정 대상이다.

**왜 이렇게?**

* 두 칸을 차례로 누르는 2단계 투구는 루즈했다. 카드 한 장 + 탭 한 번으로 줄인다.
* 어려운 공을 던지면 코스트를 덜 받는다. **투구와 카드 기습 사이에 자원 트레이드오프**가 생긴다.
* 볼은 별도 카드가 아니라 **칸 선택으로 만든다.** 타자는 시작 칸과 카드 방향을 읽어 볼인지 판단해야 한다.

## 6. 공격 ① 타격·카운트 [변경]

### 6.1 카운트

| 카운트 | 조건 | 결과 |
| --- | --- | --- |
| 스트라이크 | 아래 표의 모든 실패 | **2스트라이크 = 아웃** |
| 볼 | 볼에 스윙하지 않음 | **2볼 = 2루 출루 (150점)**, 주루 없음 |

| 스트라이크가 되는 경우 |
| --- |
| 옆 칸 빗맞음 (**파울**) — 단 25%는 LUCKY로 안타 ([6.3](#63-lucky)) |
| 대각선 반대 칸 |
| 타이밍 오차 0.230초 초과 |
| 스트라이크 존 공에 스윙하지 않음 |
| **볼에 스윙** |

* 파울로 2스트라이크가 되어도 아웃이다 (실제 야구와 다르다).
* 카운트는 타석이 끝나면 초기화된다.

### 6.2 타이밍 → 생명

오차는 공이 도착한 순간과 칸을 누른 순간의 차이다. **쳐야 할 칸은 도착 칸**이다.

| 등급 | 오차 | 생명 [가안] | 보너스 속도 [미정] |
| --- | --- | ---: | --- |
| **JUST** | 0.030초 이내 | 5 | 앞 구간 가속? |
| **PERFECT** | 0.070초 이내 | 4 | 앞 구간 가속? |
| **GREAT** | 0.140초 이내 | 3 | — |
| **GOOD** | 0.230초 이내 | 2 | — |
| **LUCKY** (빗맞음 25%) | 0.230초 이내 | 1 | — |

* CHANCE(목표 루타)는 **없다.** 등급은 생명 수만 정한다.
* 잘 친 타구에 **앞 구간 보너스 속도**를 줄지는 미정이다. 주면 "잘 치면 멀리 간다" 가 직관적이지만, 생명이 많은 타자가 더 빨리 가서 안전까지 겹친다.

### 6.3 LUCKY

* 빗맞음(옆 칸) 중 **25%**. 파울 대신 **생명 1개로 주루를 시작**한다 [가안].
* 수비 코스트 -2 페널티는 **삭제** [변경]. 카드 잠금 2초는 [미정].

**왜 이렇게?**

* 1B 효율이 너무 좋았다. 빗맞음은 원칙적으로 파울이고, LUCKY만 살려 둔다.
* 점수 차(50 → 1000)를 크게 벌려 "잘 친 타구가 멀리 가는 것" 을 극적으로 만든다.

## 7. 공격 ② 주루 — 생명제 [변경]

### 7.1 구간

* 주자는 **자동으로 달린다.** 조작은 회피뿐이다.
* 구간은 **4개** (홈→1루, 1루→2루, 2루→3루, 3루→홈). 상한 없이 **생명이 남아 있으면 계속 달린다.**
* 구간 사이에서 멈추지 않는다. 베이스를 밟는 순간 날아오던 장애물은 다음 구간으로 이어진다.

| 구간 | 웹 프로토타입 | 단축안 [가안] |
| --- | ---: | ---: |
| 홈 → 1루 | 5.0초 | 4.0초 |
| 1루 → 2루 | 5.5초 | 4.5초 |
| 2루 → 3루 | 8.0초 | 5.5초 |
| 3루 → 홈 | — | 6.0초 |

* **뒤 구간일수록 어렵다.** 3루 이후는 장애물 밀도·속도가 가장 높다 ([9.2](#92-난이도)).

### 7.2 생명

* 타격 등급이 정한 수로 시작한다. 최대 [가안] 5.
* **WRONG / TOO LATE = 생명 -1.** 회피 성공은 생명을 회복하지 않는다 [가안].
* 헛회피는 생명을 깎지 않고 **0.35초 경직**만 준다.
* 관객 난입 회피 보상 [가안]: **생명 +1** (피버가 없어졌으므로 보상을 바꾼다).

### 7.3 생명 0 [미정 — 권장안 A]

| 안 | 생명 0이 되면 | 특징 |
| --- | --- | --- |
| **A (권장)** | **마지막으로 밟은 베이스에서 세이프.** 그 베이스 점수를 받는다. 1루도 못 밟았으면 아웃 | 1루·2루·3루 점수가 자연스럽게 나온다. 아웃은 타격 실패와 1루 전 사망뿐 |
| B | 아웃. 밟은 베이스 점수는 받는다 | 홈런이 아니면 전부 아웃이라 2아웃 조기 종료가 거의 항상 걸린다. 사실상 공격 2회 |

* A로 가면 "구간 성공 0 아웃", "한 구간 TOO LATE 2회 아웃" 은 없앤다. 생명이 아웃과 세이프를 모두 대신한다.

### 7.4 장애물과 정답 (유지)

| 위험 위치 | 누를 칸 | 캐릭터 동작 | 규칙 |
| --- | --- | --- | --- |
| 좌상 (공·관객) | **우상** | 오른쪽으로 상체를 피한다 | 반대쪽 |
| 우상 (공·관객) | **좌상** | 왼쪽으로 상체를 피한다 | 반대쪽 |
| 좌하 (태클) | **좌하** | 왼쪽 다리를 들어 넘긴다 | 같은 쪽 |
| 우하 (태클) | **우하** | 오른쪽 다리를 들어 넘긴다 | 같은 쪽 |

### 7.5 회피 판정 (유지, 보상만 변경)

* 유효 창: 충돌 0.45초 전부터. 누르는 순간 판정, 칸마다 따로.

| 판정 | 조건 | 생명 | 수비 코스트 |
| --- | --- | --- | --- |
| **PERFECT** | 정답 칸, 충돌 0.20초 이내 | 유지 | +1 |
| **NICE** | 정답 칸, 그보다 일찍 | 유지 | +1 |
| **WRONG** | 장애물이 있는데 정답이 아닌 칸 | **-1** | — |
| **TOO LATE** | 끝까지 누르지 않고 충돌 | **-1** | — |
| **헛회피** | 유효 창 안에 장애물이 없는데 누름 | 0.35초 경직 | — |

* PERFECT와 NICE의 차이는 연출·기록뿐이다 [가안]. 연속 배율은 없앤다.

### 7.6 아웃 [변경]

| 아웃 | 조건 |
| --- | --- |
| 삼진 | 2스트라이크 |
| 1루 전 사망 | 1루를 밟기 전에 생명 0 (권장안 A 기준) |

* 아웃되면 0.75초 뒤 결과로 넘어간다.

**왜 이렇게?**

* 목표 루타를 정해 두면 잘 피해도 더 갈 수 없어 후반 회피가 심심했다. **생명 = 얼마나 멀리 갈 수 있는가**로 바꾸면 모든 회피가 거리로 이어진다.
* 피버는 "3루에서 홈런을 노리는 장치" 였다. 상한이 사라지면 홈런은 **끝까지 안 맞는 것**으로 대신하므로 피버를 뺀다.

## 8. 수비 ② 코스트·장애물 카드

### 8.1 코스트 [변경]

* **타석마다 지급**한다. 지급량은 그 타석에 쓴 **투구 카드의 난이도**로 정한다 ([5.3](#53-투구-카드-6종-가안)).
  시간 초과 무작위 직구는 직구 기준 [가안].
* 타자가 필드·카드 장애물을 **피할 때마다 +1.** 관객 난입은 주지 않는다.
* 최대 **10.** 남은 코스트는 다음 타석으로 이월한다 [가안].
* 시간으로 차지 않는다. 반 이닝 시작 코스트는 없다 (첫 타석 지급이 시작 코스트다).

### 8.2 덱과 손패 [변경]

* 카드 풀 **8종**(C01~C08) 중 **6장을 골라** 덱을 만든다. 손패 **3장**.
  * 누가 고르는가: **플레이어가 매치 전에 고른다** [가안]. 이 경우 "덱 편집" 이 만들지 않는 것 목록에서 빠진다.
* 카드 위치는 손패에 들어올 때 무작위로 정해져 카드에 표시된다 (C07·C08은 위치 없음).
* 누르면 즉시 발동하고 코스트가 빠진다. 발동 후 **전역 쿨다운 0.5초** 동안 모든 카드를 쓸 수 없다.
* 쓴 카드는 덱으로 돌아가고, 손패에 있는 카드와 방금 쓴 카드를 뺀 나머지에서 보충한다.

## 9. 필드 장애물·난이도

### 9.1 생성 방식 (유지)

패턴 + 구간 예산 + 가중 랜덤. 패턴 표는 [기획서.md 10.1](기획서.md#101-생성-방식--패턴--예산--가중-랜덤) 그대로.

### 9.2 난이도 [변경]

* 타석 수 레벨은 **없앤다.** 난이도는 **구간이 뒤로 갈수록** 오른다.
* 구간 4개에 예산·속도·간격을 따로 둔다 [가안]:

| 구간 | 예산 | 속도 | 간격 |
| --- | ---: | ---: | ---: |
| 홈 → 1루 | 1 | ×1.00 | ×1.30 |
| 1루 → 2루 | 2 | ×1.10 | ×1.10 |
| 2루 → 3루 | 3 | ×1.22 | ×0.95 |
| 3루 → 홈 | 3 | ×1.35 | ×0.85 |

* 학습 단계(정답 화살표, 공만 나오는 구간)를 어디에 둘지는 [미정]. 이전엔 Lv.1 타석에 있었다.
* 안전 보정(첫 장애물 여유 0.55초, 유효 창 겹침 방지, 구간마다 최소 1개)은 유지한다.

### 9.3 바람·관객 난입 (유지)

* 바람: 장애물마다 속도 ±5~10%.
* 관객 난입: 구간마다 7%, 위 좌/우. 보상은 [7.2](#72-생명) 참고.

## 10. 화면·뷰 [변경]

### 10.1 원칙

* **봐야 할 정보를 먼저 정하고 카메라를 정한다.** 장면마다 "이 순간 플레이어가 읽어야 하는 것" 이 다르다.
* 카메라 값(높이·거리·각도·FOV)은 **Unity 인스펙터로 조절**할 수 있게 만들고 플레이하며 맞춘다.

### 10.2 장면별 뷰 [가안]

| 장면 | 공격자가 봐야 하는 것 | 공격자 뷰 | 수비자가 봐야 하는 것 | 수비자 뷰 |
| --- | --- | --- | --- | --- |
| 투구 선택 | 투수 (읽을 정보 없음) | 타자 뒤 | 손패, 4칸 | 투수 시점 + 투구 손패 |
| 투구·타격 | **공이 위 칸인지 아래 칸인지**, 휘는 방향 | 타자 뒤. **현재 상·하 구분이 안 된다 → 카메라 높이·칸 표시 재설계** | 공의 궤적 | 투수 시점 |
| 주루 | 다가오는 장애물, 생명, 다음 베이스 | 주자 뒤 3인칭 | **필드 장애물(약 1초 먼저)**, 주자 위치, 손패 | 필드 전경 + 장애물 손패 |
| 결과 | 결과 문구 | 공통 | 결과 문구 | 공통 |

* 수비자는 필드 장애물 생성을 공격자보다 **약 1초 먼저** 본다. 그것을 보고 카드를 얹어 겹치게 만드는 것이 수비의 플레이다.
* 수비자 화면은 같은 스냅숏을 다른 카메라로 그린다. 통신 구조는 바뀌지 않는다.

### 10.3 주루 HUD [변경]

장애물을 보느라 시선이 못 가므로 **정보를 최소로** 한다.

| 위치 | 내용 |
| --- | --- |
| 오른쪽 | **하트** (남은 생명) |
| 위쪽 | **다음 베이스까지 남은 거리** (바 또는 숫자) |
| 그 외 | 점수·이닝·아웃·공격 횟수는 주루 중에는 숨기거나 작게 |

### 10.4 연출

* 피버·CHANCE 연출은 삭제. 생명이 깎일 때 하트가 깨지는 연출, 베이스 통과 문구는 유지.
* 볼 판정: "BALL" 문구, 2볼 출루 연출.
* 그 외는 [기획서.md 11.3](기획서.md#113-연출) 을 따른다.

### 10.5 로비

* 버튼: PvP 대전 / 연습 · 공격 / 연습 · 수비. 덱 6장 선택 화면 [가안].

## 11. 연습 모드

* 역할을 고르고 봇과 대결한다. **반 이닝(공격 3회)** 만 한다.
* 봇은 확률로만 움직인다.

| 봇 | 행동 [가안] |
| --- | --- |
| 봇 수비 · 투구 | 손패에서 무작위 카드 + 무작위 칸. 볼이 되는 조합도 그대로 낸다 |
| 봇 수비 · 카드 | 주루 중 0.5초마다 35% 확률로 쓸 수 있는 카드 중 하나 |
| 봇 타자 · 타격 | 도착 칸 70% / 옆 칸 20% / 대각선 10%. 볼에는 30% 스윙. 타이밍 오차 표준편차 0.09초 |
| 봇 타자 · 회피 | 정답 85% / 오답 8% / 무반응 7%. C03·C04에 30%, C07에 50% 속는다 |

* 새 규칙의 **1이닝 평균 점수와 플레이타임**은 이 봇을 돌려 측정한다.

| 바람 | ±5~10% | 유지 |

## 부록 B. Unity 통신 구조

원칙은 웹 프로토타입과 같다. **"불합리하게 느껴지지 않을 정도"** 가 목표다.

| 역할 | 하는 일 |
| --- | --- |
| 공격자 기기 | 타격·회피·생명·아웃을 **모두 판정**하고 장면 스냅숏을 보낸다 |
| 수비자 기기 | 스냅숏을 받아 **자기 카메라로** 그린다. 투구 카드·장애물 카드 입력을 보낸다 |
| 호스트 | 아웃·점수·이닝·공격 횟수·핸디캡·승패만 관리한다 |

* 회피는 입력이 일어나는 공격자 기기에서 판정하므로 **입력 지연이 없다.** 이것이 불합리함을 막는 핵심이다.
* 카드 발동은 수비자 → 공격자로 한 번 건넌다. 출발 시각을 실어 보내 양쪽 시계를 맞춘다.
* 호스트가 누구인지(두 플레이어 중 하나 / 별도 서버)는 Unity 넷코드 선택에 따른다 [미정]. 어느 쪽이든 위 역할 분담은 같다.
* 패킷 종류는 웹 프로토타입 [부록 B](기획서.md#부록-b-네트워크-구조패킷)를 기준으로 하되, `PITCH_SELECT` 는 카드 ID + 시작 칸으로, 피버 패킷은 삭제, 카운트·생명·공격 횟수를 추가한다.

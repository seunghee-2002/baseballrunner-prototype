# 아이디어 발전 과정 — AI 대화 요약

이 게임 아이디어를 만든 ChatGPT 대화("게임 장르 정하기")를 **무엇을, 왜 그렇게 정했는지** 중심으로 요약한 문서다.

* 원본 대화: <https://chatgpt.com/share/6aa74c89-6990-83ee-a121-519ef87bea0d>
* 이 대화의 마지막 결과물이 원본 `기획안.md`(PvE, 삭제됨)다. 현재 게임 규칙은 [`기획서.md`](기획서.md)에 있다.

## 1. 한눈에 보기

> **타격은 "얼마나 멀리 갈 가능성이 있는가"를, 주루는 "실제로 얼마나 멀리 갈 것인가"를 정한다.**

| 항목 | 결정 |
| --- | --- |
| 소재 | 야구. 단, 야구 규칙을 재현하는 게임이 아니라 **야구를 소재로 한 아케이드** |
| 핵심 행동 | **맞춘다**(타격) + **피한다**(주루) |
| 핵심 구조 | 루타는 칠 때 정해지지 않고, **주루 성과로 오르내린다** (CHANCE) |
| 시점 | 주자 뒤 **3인칭 러너 시점** |
| 주루 조작 | 3레인 이동이 아니라 **화면 네 귀퉁이를 눌러 회피 동작** |
| 난이도 | 실력 + 운. **운은 상황을 정하고, 실력은 상황을 해결한다** |

노리는 감정: **"이거 하나만 더 성공하면 3루다" → 욕심내서 도전 → "한 판만 더."**

## 2. 출발 조건

| 항목 | 내용 |
| --- | --- |
| 기간 | 약 3개월 |
| 인원 | 3명. 팀장(게임 제작 경험 여러 번) + **개발 경험이 거의 없을 수 있는 팀원 2명** |
| 장르 | 간단한 (하이퍼)캐주얼 |
| 피할 것 | 전작 「균형의 달인」 같은 **물리·퍼즐** 계열. 이번엔 다른 느낌으로 |

대화에서 정한 아이디어 선정 기준:

* 장르 이름보다 **플레이어가 반복하는 행동(동사) 하나**를 먼저 정한다.
* 초보 팀원 2명이 나눠 맡을 수 있어야 한다.
* 1~2주 안에 프로토타입으로 재미를 검증할 수 있어야 한다.
* 아트·기획·개발량이 폭발하지 않아야 한다.

## 4. 팀장이 직접 낸 핵심 아이디어

게임의 뼈대는 대부분 사용자(팀장)의 제안에서 나왔다.

### ① 쏜다 + 피한다 = 야구

> 타자일 때는 투수가 던진 공을 조준해서 맞히고, 출루할 때는 날아오는 장애물을 피한다.

두 행동이 억지로 붙은 것이 아니라 **타격 → 주루라는 야구의 자연스러운 흐름**으로 이어진다는 점이 가장 좋은 평가를 받았다.

### ② 루타는 칠 때 정해지지 않는다

> 2루타 판정의 공을 쳤어도, 주루를 완전히 잘하면 3루타가 되고, 못하면 1루타나 아웃이 된다.

* "잘 치면 결과가 나온다"가 아니라 **"잘 치면 좋은 기회를 얻는다"** 가 된다.
* 플레이어는 "2루타는 확보했네"가 아니라 **"여기서 잘하면 3루까지 간다!"** 라고 느낀다.
* 타격을 잘할수록 **더 높은 상한선**을 얻는 구조다.

### ③ 러너 시점

> 주루로 달려가는 화면 안에서 멀리서 날아오는 장애물을 피한다. 쿼터뷰가 아니다.

1인칭과 3인칭 중에서는 **내 캐릭터와 회피 방향이 보이는 3인칭**으로 정했다.

### ④ 3레인 대신 네 귀퉁이 회피 동작

> 야구 주로는 좁으니, 좌상·좌하·우상·우하에 각각 동작을 둔다.

사용자가 든 예시:

| 위험 | 누르는 곳 | 동작 |
| --- | --- | --- |
| 왼쪽 위에서 공이 날아온다 | 오른쪽 위 | 머리를 오른쪽으로 기울인다 |
| 오른쪽 아래에서 1루수가 달려든다 | 오른쪽 아래 | 발을 들어 피한다 |

* 이 예시가 지금의 **"위는 반대쪽, 아래는 같은 쪽"** 규칙의 출발점이다.
* 3레인은 레인만 보고 움직이면 되지만, 이 방식은 **위험 위치 + 위험 종류 + 맞는 동작**을 함께 판단해야 한다.

> 참고: 대화 속 AI의 정리표와 원본 기획안 §11은 아래쪽도 반대쪽으로 바꿔 적었다.
> 이후 사용자의 원래 예시대로 **아래는 같은 쪽**으로 확정됐다.

### ⑤ 실력만이 아니라 운도

> 3레인은 너무 쉽다. 실력 요소도 있지만, 운 요소도 있어야 난이도를 조절할 수 있다.

이 요구가 **패턴 랜덤 조합**과 **"운은 상황, 실력은 해결"** 원칙으로 이어졌다.

## 5. 대화에서 받아들인 설계 원칙

| 원칙 | 내용 |
| --- | --- |
| 야구는 소재로만 | 수비 AI, 볼/스트라이크, 주자 관리는 넣지 않는다. 대화에서의 평가는 "야구 게임"으로 만들면 5/10, **"야구 소재 타격 + 회피 아케이드"로 만들면 8~9/10** |
| 두 파트는 다른 실력 | 타격 = 정확도·타이밍·조준 / 주루 = 반응 속도·판단·회피 |
| 버튼이 아니라 화면 영역 | 네 버튼을 화면에 깔면 QTE 게임처럼 보인다. **화면 전체를 네 영역**으로 쓴다 |
| 좋은 랜덤만 쓴다 | 멀리서 보이는데 방향만 랜덤 → 좋은 랜덤. 화면 밖에서 갑자기 나와 반응할 수 없음 → "억까" |
| 암기 게임 방지 | 고정 패턴이 아니라 여러 상황을 랜덤으로 조합해 **보고 반응**하게 한다 |
| 한 번에 많이 던지지 않는다 | 네 방향에서 쏟아지면 탄막 게임이 된다. 처음엔 한 번에 1~2개 |
| 3D 러너를 제대로 만들 필요 없음 | 멀리서 작게 → 가까워지며 커지는 연출로 "날아오는 느낌"을 충분히 낸다 |

## 6. 검토했다가 택하지 않은 안

| 안 | 택하지 않은 이유 |
| --- | --- |
| 물리 기반 캐주얼 (던지기·쌓기 등) | 전작 「균형의 달인」과 개발 성격이 겹친다 |
| 실제 야구 게임 (규칙 재현) | 수비 AI·주자 관리 등으로 개발량이 폭발한다 |
| 타격이 루타를 바로 정하고, 주루는 난이도만 결정 | 사용자의 CHANCE 방식이 긴장감이 훨씬 크다 |
| 필드 위에서 네 방향 자유 이동 (쿼터뷰) | 원하는 화면이 아니고, 야구보다 닷지 게임이 된다 |
| 1인칭 시점 | 내 위치와 피한 방향을 알기 어렵고 주루 느낌이 약하다 |
| 3레인 이동 | 레인만 보고 움직이면 기계적이고 너무 쉽다 |

## 7. 비슷한 게임 조사 (대화 당시 ChatGPT 검색 결과)

| 게임 | 겹치는 점 | 다른 점 |
| --- | --- | --- |
| Baseball Runner | 야구 + 달리기 + 장애물 회피 | 달리며 피하다 스윙하는 구조. 타격이 주루 결과를 만드는 연결이 없다 |
| BASEBALL 9 | 타격 후 주루를 직접 조작 | 실제 야구 상황에서 베이스를 고르는 방식. 액션 회피가 아니다 |
| MLB The Show 25 | 태그를 피하는 순간 회피 동작(QTE) | 일부 상황의 기술일 뿐, 주루 전체가 반응 게임은 아니다 |
| Looney Tunes: Batter Up! | 위치 판단 → 타이밍 입력 | 3레인 구조이고 주루가 없다 |

**결론**: "야구 + 달리기 + 장애물" 조합은 이미 있다. 하지만
**타격으로 루타 CHANCE 결정 → 3인칭 주루 → 상황별 회피 동작 → 최종 루타 변동**
을 묶은 직접 경쟁작은 찾지 못했다.

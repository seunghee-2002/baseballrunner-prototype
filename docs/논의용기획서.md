## 1. 게임 개요

> **타격으로 생명을 얻고, 주루 회피로 생명을 지키며, 생명이 남아 있는 한 홈까지 달리는 1v1 대전.**

| 항목 | 내용 |
| --- | --- |
| 장르 | 반응형 야구 액션 러너 |
| 플랫폼 | 모바일 세로 화면(9:16), Unity 3D |
| 대전 | 1v1, 3이닝 (초 / 말), 플레이타임 목표 5분 |
| 공격자가 하는 일 | **맞춘다**(타격) + **피한다**(주루) |
| 수비자가 하는 일 | **던진다**(투구 카드) + **기습한다**(장애물 카드) |
| 소재 | 야구 소재 아케이드. 실제 경기 규칙은 재현하지 않는다 |
| 시점 | 공격자와 수비자는 **서로 다른 뷰**를 본다 ([10장](#10-화면뷰)) |

### 핵심 흐름

```text
[수비] 투구 카드 + 칸 탭 → [공격] 타격 → 생명 획득 → 주루 (수비는 장애물 카드로 기습)
      → 생명이 남은 채 홈 도착 = 홈런 / 생명 소진 = 거기까지
```

### 노리는 순간

* **공격**: 빗맞은 타구라도 **하나도 안 맞으면 홈런**이다. 생명 하나를 쥐고 3루를 도는 순간.
* **수비**: 필드 장애물을 먼저 보고, 타자의 손을 **읽어 카드를 얹는** 심리전.

## 2. 핵심 설계 원칙

| 원칙 | 뜻 |
| --- | --- |
| **타격 = 생명, 주루 = 거리** | 타격은 목표 루타가 아니라 **생명 수**를 준다. 주루는 생명이 다할 때까지 이어지고, 어디까지 갔느냐가 점수다 |
| **상한 없는 주루** | 어떤 타구든 이론상 홈런이 가능하다 |
| **판정은 한곳에서** | 타격·회피·아웃은 공격자 기기에서 판정한다 ([부록 B](#부록-b-통신-구조)) |
| **4분할 = 방향 입력** | 네 칸은 "어느 방향" 을 정하는 입력이다. 회피 방향, 투구 시작 칸, 스윙 코스 |
| **자유 이동 없음** | 주자는 자동으로 달리고, 조작은 회피뿐이다 |
| **위는 반대쪽, 아래는 같은 쪽** | 공은 반대쪽으로 상체를 피하고, 태클은 같은 쪽 다리를 든다. 일부러 넣은 혼란 요소다 |
| **충돌 직전이 최고 판정** | 일찍 누를수록 좋은 구조가 아니다. 눈에 보이는 충돌과 판정이 맞아야 손이 납득한다 |
| **실패 이유가 보여야 한다** | 틀리면 잘못 누른 쪽으로 실제로 피한 뒤 맞고, 정답을 글로 보여준다 |
| **좋은 랜덤만 쓴다** | 필드 장애물은 패턴 + 예산 + 가중 랜덤으로 만든다. 운은 상황을 정하고, 실력은 상황을 해결한다 |
| **겹침은 다중 카드로만 생긴다** | 필드 장애물끼리는 겹치지 않게 보정하고, 카드에는 전역 쿨다운이 있다. 동시 위험은 한 장이 둘을 내는 카드에서만 나온다 |
| **수비자는 먼저 보고, 공격자는 읽을 수 있다** | 수비자는 필드 장애물을 약 1초 먼저 본다. 카드 기습은 색과 경고로 드러나서, 공격자가 읽고 반응할 수 있다 |
| **등급 체계는 하나** | 타격도 회피도 PERFECT / GREAT / GOOD / BAD 네 등급이다 |
| **최대 공격 시간이 있다** | 최대 공격 횟수가 정해져 있고, 만약 아웃을 당한다면 공격 기회가 끝난다.|
| **실패는 짧게** | 아웃 후 0.75초 뒤 결과로 넘어간다 |
| **장애물과 카드는 데이터** | 새 장애물·카드는 데이터 표에 한 줄을 더해 만든다 |

## 3. 매치 구조

### 3.1 한 판 흐름

```text
로비 → 방 입장 → 1회 초 → 1회 말 → (핸디캡 판정) → 2회 초 → … → 3회 말 → 매치 결과
```

| 항목 | 내용 |
| --- | --- |
| 이닝 수 | **3이닝** [가안]. 실제 플레이타임을 측정한 뒤 조정한다 |
| 반 이닝 종료 | **공격 횟수 3회**를 다 쓰면 끝난다. 그 전에 **2아웃**이 나오면 조기 종료 |
| 공수 교대 | 역할이 바뀐다. 수비 코스트·장애물 손패·투구 손패가 초기화된다. 안내 3초 |
| 매치 결과 | 득점 합계 비교. **동점은 무승부** |

* 공격 횟수는 타석 수다. 파울·볼로 다시 던지는 것은 같은 타석이므로 횟수를 쓰지 않는다.
* 2아웃은 종료 조건이 아니라 **조기 종료 조건**이다.

### 3.2 핸디캡

* 이닝이 끝날 때 점수를 비교해, **뒤진 쪽의 다음 이닝 공격 횟수를 +1** 한다.
* 발동 기준: **점수 차가 공격 찬스 1회로 뒤집기 힘들 때.**
  현재 기준값은 **1000점**(한 타석 최대 점수 = 홈런)이다 [가안].
  봇 대 봇 200경기에서 **1이닝(초+말) 평균 2158점**, 이닝이 끝날 때 **31%** 가 발동했다.
  사람 대 사람 데이터로 다시 본다.
* 마지막 이닝 말에는 다음 이닝이 없으므로 핸디캡이 없다.

**왜 이렇게?**

* 뒤진 쪽에 타격 판정을 후하게 주면 실력 측정이 흐려지고, 들키면 고무줄로 느껴진다.
* 앞선 쪽의 수비 코스트를 깎으면 앞선 쪽이 구경만 하게 된다.
* 공격 횟수 +1은 **양쪽이 게임을 온전히 한 타석 더 하는** 방법이다.

### 3.3 한 타석 흐름

| 단계 | 시간 | 내용 |
| --- | --- | --- |
| 투구 선택 | **구질 3초 → 칸 3초** | 수비자가 **구질을 고른 뒤 시작 칸을 탭한다.** 단계마다 시간을 새로 센다 ([5.1](#51-입력)) |
| 투구 | 약 0.55 ~ 1.40초 | 카드와 칸에 따라 궤적이 정해진다 (기본 1.15초 × 카드 배율 × ±8%) |
| 타격 결과 | 1.0초 | 안타면 생명을 보여주고 주루로. 스트라이크·볼이면 카운트를 올리고 **다시 투구 선택으로**. 2볼이면 2루에서 주루 시작 |
| 주루 | 생명이 다하거나 홈까지 | 구간 4개 (홈 → 1루 → 2루 → 3루 → 홈) |
| 타석 결과 | 1.5초 [가안] | 결과 화면 뒤 자동으로 다음 타석 |

* 한 타석에 투구는 최대 3번이다 (스트라이크 1 + 볼 1 + 마지막).

### 3.4 득점과 아웃

| 결과 | 1루 | 2루 | 3루 | 홈런 | 아웃 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 점수 | 50 | 150 | 400 | 1000 | 0 |

* 점수는 **실제로 밟은 마지막 베이스**로 정한다. 주자를 베이스에 남기지 않는다.
* 2볼 출루는 **2루에서 주루를 시작**한다 ([6.4](#64-2볼-출루)). 2루를 이미 밟은 상태이므로 최소 150점이다.

### 3.5 플레이타임 [가안]

한 타석 최대 시간 (투구 3회 + 주루 홈까지 + 결과) 기준의 상한이다.

| 구성 | 시간 |
| --- | --- |
| 투구 1회 (구질 3 + 칸 3 + 비행 1.4 + 결과 1.0) | 약 8.4초 |
| 투구 3회 | 약 25초 |
| 주루 홈까지 (4.0 + 4.5 + 5.5 + 6.0) | 20초 |
| 타석 결과 | 1.5초 |
| 한 타석 최대 | 약 47초 |
| 반 이닝 최대 (3타석) | 약 2분 20초 |
| 3이닝 최대 (반 이닝 6 + 공수 교대 5회) | 약 14분 |

* 실제로는 아웃·짧은 주루가 섞여 훨씬 짧다. **봇 대 봇으로 평균을 측정**한 뒤 이닝 수·구간 시간을 조정한다.

### 3.6 방과 연결

* 방은 하나이고 먼저 들어온 2명만 들어간다.
* 한쪽이 나가면 남은 쪽에 "상대가 나갔습니다" 를 띄우고 로비로 돌아간다.

## 4. 조작

화면을 네 칸으로 나눈다. **네 칸은 "방향" 을 정하는 입력**이다.

|  | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| **위** | 좌상 | 우상 |
| **아래** | 좌하 | 우하 |

| 입력 | 공격자 | 수비자 |
| --- | --- | --- |
| 4분할 칸 | 투구 중: 스윙 코스 / 주루 중: 회피 방향 | 투구 카드를 고른 뒤: **시작 칸** |
| 투구 손패 (하단, 3장) | — | 투구 선택 중에만. 카드를 고른 뒤 칸을 탭 |
| 장애물 손패 (하단, 3장) | — | 주루 중에만. 누르면 즉시 발동 |

* 칸마다 따로 입력을 받는다. **두 손가락으로 두 칸을 동시에 눌러도 각각 판정된다.**
* PC 조작 [가안]: 좌상 `Q` / 우상 `E` / 좌하 `A` / 우하 `D`, 카드 `1`~`3`, 직구 `F`.

**왜 이렇게?**

* 버튼을 화면에 깔면 QTE 게임처럼 보인다. **화면 자체를 입력 영역**으로 쓴다.
* 타격·회피·투구가 같은 네 칸이라 손이 체계 하나만 익히면 된다.

## 5. 수비 ① 투구 카드

투구는 **카드가 공의 움직임을, 칸이 시작 위치를** 정한다.

### 5.1 입력

투구 선택은 **두 단계를 차례로** 한다. 단계마다 제한 시간을 새로 센다.

1. **구질 단계 (3초)** — 투구 손패 3장 또는 직구 버튼 중 하나를 고른다.
   시간이 지나면 **직구로 정해지고** 바로 칸 단계로 넘어간다.
2. **칸 단계 (3초)** — 4분할 중 한 칸을 탭한다 → **시작 칸**.
   이 단계에서는 **구질을 바꿀 수 없다.** 시간이 지나면 고른 구질로 **무작위 칸**에 던진다.
3. 공은 시작 칸에서 카드의 이동 방향대로 움직여 **도착 칸**에 온다.
   * 이동 방향이 없는 카드(직구·강속구)는 시작 칸 = 도착 칸.
   * 이동한 결과가 **네 칸 밖**이면 **볼**이다.

* **수비자는 투수 뒤에서 본다.** 수비자가 탭하는 칸도, 카드 이름의 방향("좌→우")도 **수비자 화면 기준**이다.
  타자 시점으로는 좌우가 반대로 뒤집힌다.

예: "좌→우 슬라이더" 카드 + 좌상 탭 = 좌상에서 우상으로 휘는 변화구. 같은 카드 + 우상 탭 = 우상에서 화면 밖으로 빠지는 **볼**.

### 5.2 손패와 덱

* 투구 풀 **6장**, 손패 **3장**. 장애물 카드와는 **다른 덱**이다.
* **직구는 항상 쓸 수 있다.** 덱에 들어 있지 않고 손패 옆에 고정 버튼으로 있으며, **코스트 0**이다.
* 투구 카드는 **코스트를 쓴다.** 장애물 카드와 같은 코스트 풀에서 빠진다 ([8.1](#81-코스트)).
* 쓴 카드는 덱으로 돌아가고, 손패에 있는 카드와 방금 쓴 카드를 뺀 나머지에서 보충한다.
* **공수 교대 때마다**(자기 수비 차례가 시작될 때) 전체를 다시 섞어 3장을 받는다.

### 5.3 투구 카드 [가안]

이동 방향은 **수비자(투수 뒤) 화면 기준**이다. 비행 시간은 **기본 1.15초 × 아래 배율**이다.

| ID | 이름 | 이동 | 비행 시간 배율 | 구속 | 코스트 |
| --- | --- | --- | ---: | --- | ---: |
| — | 직구 (고정) | 없음 | 0.78 | 빠름 | 0 |
| P1 | 좌→우 슬라이더 | 오른쪽 한 칸 | 1.00 | 보통 | 1 |
| P2 | 우→좌 슬라이더 | 왼쪽 한 칸 | 1.00 | 보통 | 1 |
| P3 | 낙차 포크 | 아래 한 칸 | 1.00 | 보통 | 1 |
| P4 | 라이징 | 위 한 칸 | 1.00 | 보통 | 1 |
| P5 | 대각 커브 | **대각선 반대 칸** | 1.13 | 느림 | 2 |
| P6 | 강속구 | 없음 | 0.52 | 매우 빠름 | 2 |

* **구속에는 랜덤성이 있다.** 구질마다 기본 구속이 정해져 있고, 투구마다 **±8%** [가안] 안에서 달라진다. 매번 같은 타이밍이면 손이 외워 버린다.
* 볼이 되는 조합: P1 + 오른쪽 열, P2 + 왼쪽 열, P3 + 아랫줄, P4 + 윗줄.
  **P5는 항상 대각선 반대 칸으로 휘므로 볼이 되지 않는다.** 직구·P6도 이동이 없어 볼이 되지 않는다.
* **변화구는 비행 10% 지점부터 휜다.** 막판 반응 싸움이 되지 않게, 휘는 방향을 눈으로 읽을 시간을 준다.
  휘기 시작할 때 시작 칸 바깥으로 한 번 부풀었다가 도착 칸으로 들어온다 (화면 연출일 뿐 판정과 무관).
* 카드 이름·구성·코스트 값은 전부 조정 대상이다.

**왜 이렇게?**

* 카드 한 장 + 탭 한 번. 투구 선택이 늘어지지 않는다.
* 투구 카드와 장애물 카드가 **같은 코스트를 나눠 쓴다.** 어려운 공에 코스트를 쓰면 주루에서 기습할 코스트가 준다.
* 볼은 별도 카드가 아니라 **칸 선택으로 만든다.** 타자는 시작 칸과 카드 방향을 읽어 볼인지 판단해야 한다.

## 6. 공격 ① 타격·카운트

### 6.1 카운트

| 카운트 | 조건 | 결과 |
| --- | --- | --- |
| 스트라이크 | 아래 표의 모든 실패 | **2스트라이크 = 아웃** |
| 볼 | 볼에 스윙하지 않음 | **2볼 = 2루 출루.** 2루에서 주루를 시작한다 ([6.4](#64-2볼-출루)) |

| 스트라이크가 되는 경우 |
| --- |
| 옆 칸 빗맞음 (**파울**) — 단 25%는 LUCKY로 안타 ([6.3](#63-lucky)) |
| 대각선 반대 칸 |
| 타이밍 오차 0.230초 초과 |
| 스트라이크 존 공에 스윙하지 않음 (도착 후 0.24초까지 기다린다) |
| **볼에 스윙** |

* 파울로 2스트라이크가 되어도 아웃이다 (실제 야구와 다르다).
* 카운트는 타석이 끝나면 초기화된다.

### 6.2 타이밍 → 생명

오차는 공이 도착한 순간과 칸을 누른 순간의 차이다. **쳐야 할 칸은 도착 칸**이다. 타이밍 링은 없고, 공의 궤적과 속도를 눈으로 읽는다.

| 등급 | 오차 [가안] | 생명 | 보너스 속도 [가안] |
| --- | --- | ---: | --- |
| **PERFECT** | 0.040초 이내 | 3 | **3루까지** 1.5배 |
| **GREAT** | 0.100초 이내 | 2 | **2루까지** 1.5배 |
| **GOOD** | 0.160초 이내 | 2 | — |
| **BAD** | 0.230초 이내 | 1 | — |
| **LUCKY** (빗맞음 25%) | 0.230초 이내 | 1 | — |

* 등급은 **생명 수와 보너스 속도**를 정한다. 목표 루타는 없다.
* 보너스 속도 구간에서는 구간 시간이 1.5배 빨리 흐른다. 장애물 밀도는 그대로이므로 **그 구간의 장애물 수가 준다.**

### 6.3 LUCKY

* 빗맞음(옆 칸) 중 **25%**. 파울 대신 **생명 1개로 주루를 시작**한다 [가안].
* **수비자에게 페널티는 없다.** 코스트 차감도, 주루 시작 후 카드 잠금도 없다.

**왜 이렇게?**

* 타격은 **정확도와 타이밍**, 주루는 **반응 속도와 판단**. 두 파트가 서로 다른 실력을 요구한다.
* 빗맞음은 원칙적으로 파울이고 LUCKY만 살려 둔다. 점수 차(50 → 1000)가 커서 "잘 친 타구가 멀리 가는 것" 이 극적이다.
* 잘 친 타구는 **더 빨리 간다.** PERFECT는 3루, GREAT는 2루까지 가속이라 수비자가 기습할 시간이 준다.

### 6.4 2볼 출루

* 볼 두 개면 타자는 **2루에서 주루를 시작**한다. 2루→3루, 3루→홈 구간을 달린다.
* 생명은 **2** [가안] (GOOD과 같다). 보너스 속도는 없다.
* 2루를 이미 밟은 상태이므로 생명이 다해도 **최소 2루 (150점)** 다.

## 7. 공격 ② 주루

### 7.1 구간

* 주자는 **자동으로 달린다.** 조작은 회피뿐이다.
* 구간은 **4개** (홈→1루, 1루→2루, 2루→3루, 3루→홈). 상한 없이 **생명이 남아 있으면 계속 달린다.**
* 구간 길이는 **시간으로 고정**한다.

| 구간 | 시간 [가안] |
| --- | ---: |
| 홈 → 1루 | 4.0초 |
| 1루 → 2루 | 4.5초 |
| 2루 → 3루 | 5.5초 |
| 3루 → 홈 | 6.0초 |

* **보너스 속도**: PERFECT 타격은 3루까지, GREAT 타격은 2루까지 구간 시간이 **1.5배** 빨리 흐른다 [가안].
* 구간 사이에서 멈추지 않는다. 베이스를 밟는 순간 날아오던 장애물은 **다음 구간으로 이어진다.**
* 홈에 닿으면 남은 장애물은 사라진다.
* **뒤 구간일수록 어렵다.** 3루 이후는 장애물 밀도·속도가 가장 높다 ([9.2](#92-난이도)).

**왜 이렇게?**

* 자유롭게 움직이게 하면 야구가 아니라 닷지 게임이 된다. **조작은 쉽게, 판단은 순간적으로.**

### 7.2 생명

* 타격 등급이 정한 수로 시작한다 (PERFECT 3 / GREAT 2 / GOOD 2 / BAD 1 / LUCKY 1 / 2볼 출루 2). 최대 3.
* **회피 BAD = 생명 -1.** 회피 성공은 생명을 회복하지 않는다 [가안].
* 헛회피는 생명을 깎지 않고 **0.35초 경직**만 준다.
* 주루 중에 생명이 느는 일은 없다.

### 7.3 생명 0

* **마지막으로 밟은 베이스에서 세이프.** 그 베이스 점수를 받는다.
* 1루도 못 밟았으면 **아웃**이다.
* 2볼 출루자는 2루에서 출발했으므로 최소 2루다.

### 7.4 장애물과 정답

| 장애물 | 나오는 곳 | 오는 곳 | 노리는 곳 | 기본 속도 | 도달 시간 |
| --- | --- | --- | --- | ---: | ---: |
| **공** | 필드, 장애물 카드 | 좌상 / 우상 | 상체 | 52 | 1.92초 |
| **관객 난입** | 필드 (무작위) | 좌상 / 우상 | 상체 | 44 | 2.27초 |
| **수비수 태클** | 필드, 장애물 카드 | 좌하 / 우하 | 다리 | 46 | 2.17초 |

| 위험 위치 | 누를 칸 | 캐릭터 동작 | 규칙 |
| --- | --- | --- | --- |
| 좌상 (공·관객) | **우상** | 오른쪽으로 상체를 피한다 | 반대쪽 |
| 우상 (공·관객) | **좌상** | 왼쪽으로 상체를 피한다 | 반대쪽 |
| 좌하 (태클) | **좌하** | 왼쪽 다리를 들어 넘긴다 | 같은 쪽 |
| 우하 (태클) | **우하** | 오른쪽 다리를 들어 넘긴다 | 같은 쪽 |

* 누른 칸의 의미는 항상 **"그 방향으로 몸을 움직인다"** 로 같다.
* 장애물은 멀리서 작게 나타나 커지며 다가온다. 접근은 **거리값 하나**(100 → 0 = 충돌)로 계산한다.
* 도달 시간은 거리 100 ÷ 기본 속도다. 여기에 구간 속도 배율([9.2](#92-난이도))과 바람(±5~10%)이 곱해진다.

**왜 이렇게?**

* 3레인은 레인만 보고 움직이면 돼서 너무 쉽다. 이 방식은 **위험 위치 + 위험 종류 + 맞는 동작**을 함께 판단해야 한다.
* 위와 아래의 규칙이 다른 것은 **일부러 넣은 혼란 요소**다.

### 7.5 회피 판정

* **유효 창**: 충돌까지 **0.45초** 남은 순간부터 입력을 받는다.
* **누르는 순간 판정**하고, 누른 칸마다 따로 판정한다.

| 판정 | 조건 [가안] | 생명 | 수비 코스트 |
| --- | --- | --- | --- |
| **PERFECT** | 정답 칸, 충돌 **0.15초 이내** | 유지 | +1 |
| **GREAT** | 정답 칸, 충돌 **0.30초 이내** | 유지 | +1 |
| **GOOD** | 정답 칸, 유효 창 안 (0.45초 이내) | 유지 | +1 |
| **BAD** | 유효 창 안에 장애물이 있는데 정답이 아닌 칸을 누름, 또는 끝까지 누르지 않고 충돌 | **-1** | — |
| **헛회피** | 유효 창 안에 장애물이 하나도 없는데 누름 | **0.35초 경직** | — |

* 판정 대상: 유효 창 안에서 누른 칸이 정답인 장애물 중 **가장 가까운 것**. 정답인 것이 없으면 가장 가까운 장애물에 BAD다.
* PERFECT / GREAT / GOOD 의 차이는 연출·기록뿐이다 [가안]. 연속 배율은 없다.
* BAD는 화면 문구로 이유를 나눈다 (틀린 칸 / 반응 없음).
* 관객 난입 회피는 수비 코스트를 주지 않는다.
* 위험 두 개가 동시에 오면 **두 칸을 같이 누르면** 된다.
* 위험이 유효 창에 들어오면 **위험이 있는 칸**(정답 칸이 아님)이 잠깐 번쩍인다.

**왜 이렇게?**

* **충돌 직전이 최고 판정**이어야 눈에 보이는 충돌 순간과 판정이 맞는다.
* 아무 때나 눌러 두는 입력은 헛회피 경직으로 손해를 본다.

### 7.6 아웃

| 아웃 | 조건 | 화면 문구 |
| --- | --- | --- |
| 삼진 | 2스트라이크 | 삼진 |
| 1루 전 사망 | 1루를 밟기 전에 생명 0 | 1루에 닿지 못했다 |

* 아웃되면 결과로 넘어간다.

**왜 이렇게?**

* 목표 루타를 정해 두면 잘 피해도 더 갈 수 없어 후반 회피가 심심하다. **생명 = 얼마나 멀리 갈 수 있는가**로 두면 모든 회피가 거리로 이어진다.
* 홈런은 특별한 장치가 아니라 **끝까지 안 맞는 것**이다.

## 8. 수비 ② 코스트·장애물 카드

### 8.1 코스트

* **타석마다 정해진 양을 지급**한다. **4** [가안].
* **투구 카드와 장애물 카드가 같은 코스트를 쓴다.** 직구는 0이다.
* 타자가 필드·카드 장애물을 **피할 때마다 +1.** 관객 난입은 주지 않는다.
* 최대 **10.** 남은 코스트는 다음 타석으로 이월한다 [가안].
* 시간으로 차지 않는다. 반 이닝 시작 코스트는 없다 (첫 타석 지급이 시작 코스트다).

**왜 이렇게?**

* 투구 난이도로 지급량을 바꾸면, 타자가 쉬운 공을 못 쳤을 때 수비자가 코스트까지 더 받아 **피드백이 이상해진다.** 지급량은 고정하고, 어려운 공을 던지는 대가는 코스트 소모로 낸다.

### 8.2 덱과 손패

* 카드 풀 **8종**(C01~C08) 중 **6장을 골라** 덱을 만든다. 손패 **3장**.
  * **플레이어가 매치 전에 6장을 고른다 (덱 빌딩).** 고른 덱을 들고 매치에 들어간다.
* **카드 위치는 손패에 들어올 때 무작위로 정해져 카드에 표시된다.** (C07·C08은 위치 없음)
* 누르면 코스트가 빠지고 발동한다. 장애물 카드는 **즉시 출발**하고, 교란 카드(C07·C08)는 **경고 뒤에 적용**된다 ([8.5](#85-기습은-읽을-수-있어야-한다)).
  발동 후 **전역 쿨다운 0.5초** 동안 모든 카드를 쓸 수 없다.
* 쓴 카드는 덱으로 돌아간다. 보충은 **손패에 있는 카드와 방금 쓴 카드를 뺀 나머지**에서 무작위로 뽑는다.
* 카드에는 코스트, 위치 화살표, 이름, 종류, 단축키, 못 쓰는 이유가 표시된다.

### 8.3 카드 8종

| ID | 이름 | 종류 | 코스트 | 위치 | 효과 |
| --- | --- | --- | ---: | --- | --- |
| C01 | 고속 직격 공 | 상단 | 1 | 위 한 칸 | **1.35배 빠른** 공 |
| C02 | 슬라이딩 태클 | 하단 | 1 | 아래 한 칸 | **1.35배 빠른** 태클 |
| C03 | 대각 굴절 공 | 상단 | 3 | 위 한 칸 | 충돌 0.55초 전 **반대편 위 칸**으로 옮겨간다 (좌상 ↔ 우상) |
| C04 | 점핑 태클 | 하단 | 3 | 아래 한 칸 | 충돌 0.55초 전 **반대편 아래 칸**으로 옮겨간다 (좌하 ↔ 우하) |
| C05 | 시차 2연타 공 | 상단 | 5 | 위 한 칸 | 같은 칸으로 공 두 개, **충돌 0.20초 차이** |
| C06 | 상하 샌드위치 | 복합 | 5 | 위 한 칸 + 아래 한 칸 | 공과 태클, **충돌 0.15초 차이** |
| C07 | 변박 체인지업 | 교란 | 3 | — | 다가오는 가장 가까운 공을 **충돌 0.5초 전에 0.4배 속도로 감속** |
| C08 | 시야 흙먼지 | 교란 | 3 | — | **1초 동안 공격자 화면 가운데를 가린다** |

* 장애물 카드는 발동 즉시 먼 거리에서 출발한다. 구간 속도와 바람이 똑같이 적용된다.
* C03·C04의 칸 이동과 C07의 감속은 **유효 창이 열리기 직전**에 일어난다. 미리 나간 손은 헛회피가 된다.
  다만 카드 장애물은 **색이 달라** 무언가 다르다는 것은 미리 알 수 있다.
* 카드 장애물도 필드 장애물과 똑같이, 피하면 수비자에게 코스트 +1을 준다.

### 8.4 카드를 못 쓰는 경우

| 카드 표시 | 조건 |
| --- | --- |
| (흐리게) | 주루 중이 아님 (투구·타격 중) |
| 쿨다운 | 다른 카드를 쓴 뒤 0.5초 안 |
| 코스트 부족 | 코스트가 모자람 |
| 다가오는 공 없음 | C07: 충돌까지 **1.0초**(경고 0.5 + 감속 0.5)보다 많이 남은 공이 없음. 이미 감속했거나 경고가 붙은 공은 대상이 아니다 |
| 홈 임박 | 장애물 카드: **홈에 닿기 전에 부딪힐 수 없음** |

### 8.5 기습은 읽을 수 있어야 한다

* 카드 장애물은 필드 장애물과 **색이 다르다.** 공격자는 "카드로 나온 것" 임을 보고 이동·가속을 경계할 수 있다.
* 교란 카드(C07 감속, C08 흙먼지)는 발동 즉시 적용하지 않고, 공격자 화면에 **경고 표시 0.5초** [가안] 뒤에 적용한다.
* 어떤 카드인지, 언제 발동했는지는 공격자에게 알리지 않는다. 수비자 화면에만 "○○ 발동" 문구가 뜬다.
* 필드 장애물끼리는 겹치지 않게 보정하지만, **카드 장애물의 겹침은 보정하지 않는다.**

**왜 이렇게?**

* 카드는 **"읽고 반응하는" 심리전**을 만드는 장치다. 읽을 단서가 없으면 심리전이 아니라 억까다.
* 단서(색·경고)는 주되 정답은 주지 않는다. 색이 다른 공이 어느 쪽으로 옮겨갈지는 여전히 봐야 안다.
* 코스트가 타자의 회피 성공으로 차므로, **타자가 잘할수록 수비자의 반격 수단이 늘어난다.**
* 전역 쿨다운은 카드를 한꺼번에 쏟아 장애물을 겹치게 만드는 것을 막는다.

## 9. 필드 장애물·난이도

### 9.1 생성 방식 — 패턴 + 예산 + 가중 랜덤

필드 장애물은 **완전 랜덤으로 만들지 않는다.**

1. **패턴 풀**: 장애물 몇 개를 순서대로 묶은 패턴을 하나의 풀에 모아 둔다. 난이도 점수가 붙어 있다 (쉬움 1 / 보통 2 / 어려움 3).
2. **구간 보정**: 구간마다 예산·속도·간격·난이도 가중치를 따로 둔다 ([9.2](#92-난이도)). 같은 풀에서 뽑되 보정값이 구간의 성격을 정한다.
3. **가중 랜덤**: 예산 안에서 패턴을 뽑는다. 같은 패턴은 연달아 뽑지 않는다.
   뽑힐 확률은 **기본 가중치 × (난이도 점수 ^ 구간 가중치)** 에 비례한다. 구간 가중치가 0이면 난이도와 무관해진다.

| ID | 점수 | 기본 가중치 | 순서 |
| --- | ---: | ---: | --- |
| E1 | 1 | 5 | 공 좌상 |
| E2 | 1 | 5 | 공 우상 |
| E3 | 1 | 5 | 태클 좌하 |
| E4 | 1 | 5 | 태클 우하 |
| N1 | 2 | 4 | 공 좌상 → 공 우상 |
| N2 | 2 | 4 | 공 우상 → 공 좌상 |
| N3 | 2 | 4 | 공 좌상 → 태클 우하 |
| N4 | 2 | 4 | 태클 좌하 → 공 우상 |
| N5 | 2 | 3 | 태클 우하 → 태클 좌하 |
| H1 | 3 | 3 | 공 좌상 → 공 우상 → 태클 좌하 |
| H2 | 3 | 3 | 태클 우하 → 공 좌상 → 공 우상 |
| H3 | 3 | 3 | 공 우상 → 태클 좌하 → 공 좌상 → 태클 우하 |
| H4 | 3 | 2 | 공 좌상 → 공 좌상 → 공 우상 (같은 방향 연속으로 손이 먼저 나가게 한다) |
| H5 | 3 | 3 | 태클 좌하 → 태클 우하 → 공 좌상 → 공 우상 |

* 패턴 풀은 하나다. 어느 패턴이 어느 구간에 자주 나오는지는 [9.2](#92-난이도)의 보정값이 정한다.

### 9.2 난이도

난이도는 **구간이 뒤로 갈수록** 오른다. 타석 수에 따른 레벨은 없다.

| 구간 | 예산 | 장애물 속도 | 장애물 간격 | 어려운 패턴 가중치 |
| --- | ---: | ---: | ---: | ---: |
| 홈 → 1루 | 1 | ×1.00 | ×1.30 | 0.0 (난이도 무관) |
| 1루 → 2루 | 2 | ×1.10 | ×1.10 | 0.6 |
| 2루 → 3루 | 3 | ×1.22 | ×0.95 | 1.2 |
| 3루 → 홈 | 3 | ×1.35 | ×0.85 | 1.2 |

* 값은 [가안]. 구간 길이가 아니라 **밀도만** 올린다.
* 보너스 속도 구간은 시간이 빨리 흐를 뿐, 보정값은 그대로다.
* 학습 단계(정답 칸 화살표, 공만 나오는 구간)를 어디에 둘지는 [미정].

### 9.3 안전 보정

* 구간이 시작되고 **0.55초 뒤**에 첫 장애물이 출발한다.
* 필드 장애물끼리 **유효 창이 겹치지 않게** 간격을 벌린다 (여유 0.12초).
* 베이스 도착 0.25초 전까지 부딪힐 수 없는 장애물은 뺀다. **단, 구간마다 최소 하나는 남긴다.**

**왜 이렇게?**

* 화면 밖에서 갑자기 등장하거나, 너무 짧은 대응 시간, 필드가 스스로 만든 동시 위험은 **운이 아니라 억까**로 느껴진다.

### 9.4 바람

* 필드·카드 장애물마다 속도가 **±5~10%** 무작위로 달라진다.

### 9.5 관객 난입

* 구간마다 **7%** 확률로 관객이 위 좌/우에서 뛰어든다. 정답은 공과 같다 (반대쪽 위).
* 필드 장애물 충돌 시각과 **0.6초 이상** 떨어뜨린다.
* 보상은 없다. 피하면 다른 장애물과 같고, 실패하면 생명 -1. 수비 코스트도 주지 않는다.
* 역할은 **위쪽 장애물의 변주**다. 공과 같은 규칙인데 모양이 달라 순간 판단을 흔든다.

## 10. 화면·뷰

### 10.1 원칙

* **봐야 할 정보를 먼저 정하고 카메라를 정한다.** 장면마다 "이 순간 플레이어가 읽어야 하는 것" 이 다르다.
* 카메라 값(높이·거리·각도·FOV)은 **Unity 인스펙터로 조절**할 수 있게 만들고 플레이하며 맞춘다.
* 3D는 기본 도형만 쓰고, 회피는 **몸 기울이기·다리 들기**로만 표현한다.

### 10.2 장면별 뷰 [가안]

| 장면 | 공격자가 봐야 하는 것 | 공격자 뷰 | 수비자가 봐야 하는 것 | 수비자 뷰 |
| --- | --- | --- | --- | --- |

## 11. 연습 모드

* 서버 없이 혼자 한다. **역할을 고르고 봇과 대결**한다.
  * 연습 · 공격 = 봇 수비 상대로 공격
  * 연습 · 수비 = 봇 타자 상대로 수비
* **반 이닝(공격 3회)** 만 한다. 끝나면 "내 점수" 또는 "내준 점수" 를 보여주고 다시 / 로비로를 고른다.
* 봇은 정교한 AI가 아니라 **확률로만 움직인다.**

| 봇 | 행동 [가안] |
| --- | --- |
| 봇 수비 · 투구 | 구질 단계가 열리면 **0.8~2.2초** 뒤 쓸 수 있는 투구(직구 포함) 중 무작위, 칸 단계가 열리면 **0.2~0.6초** 뒤 무작위 칸. 볼이 되는 조합도 그대로 낸다 |
| 봇 수비 · 카드 | 주루 중 0.5초마다 35% 확률로, 쓸 수 있는 카드 중 하나를 무작위로 쓴다 |
| 봇 타자 · 타격 | 도착 칸 70% / 옆 칸 20% / 대각선 10%. 볼에는 30% 스윙. 타이밍 오차 표준편차 0.09초. 5%는 스윙하지 않는다 |
| 봇 타자 · 회피 | 정답 85% / 오답 8% / 무반응 7%. C03·C04 칸 이동에 30%, C07 감속에 50% 속는다 |

* 봇 타자의 회피 판단은 충돌까지 **0.9초** 안으로 들어온 장애물부터 시작하고, 누르는 시점은 충돌 **0.05~0.43초** 전 중 무작위다.
* 새 규칙의 **1이닝 평균 점수와 플레이타임**은 이 봇을 돌려 측정한다.
  200경기 기준 1이닝(초+말) 평균 **2158점** ([3.2](#32-핸디캡)).

## 12. 한 타석 예시

**수비자가 탭하는 칸은 수비자(투수 뒤) 화면 기준이라 타자 시점에서는 좌우가 뒤집힌다.**
장애물 카드의 위치는 뒤집지 않으므로 양쪽이 같은 칸을 본다.

### 예시 1 — GOOD 타구로 2루

## 부록 B. 통신 구조

목표는 **"불합리하게 느껴지지 않을 정도"** 다.

| 역할 | 하는 일 |
| --- | --- |
| 공격자 기기 | 타격·회피·생명·아웃을 **모두 판정**하고 장면 스냅숏을 보낸다 |
| 수비자 기기 | 스냅숏을 받아 **자기 카메라로** 그린다. 투구 카드·장애물 카드 입력을 보낸다 |
| 호스트 | 아웃·점수·이닝·공격 횟수·핸디캡·승패만 관리한다 |

* 회피는 입력이 일어나는 공격자 기기에서 판정하므로 **입력 지연이 없다.** 이것이 불합리함을 막는 핵심이다.
* 카드 발동은 수비자 → 공격자로 한 번 건넌다. 출발 시각을 실어 보내 양쪽 시계를 맞춘다.
* 타석마다 번호(`seq`)를 붙여, 이전 타석의 늦은 패킷은 버린다. 한 타석 안의 투구 순서는 `pitchNo` 로 맞춘다.
* **P2P 호스트**: 방을 연 플레이어가 호스트다. 별도 서버는 두지 않는다.
  * 호스트가 하는 일은 아웃·점수·이닝 관리뿐이고 회피 판정은 공격자 기기에서 하므로, 호스트라서 유리한 점은 없다.
  * 호스트가 나가면 매치가 끝나고 상대는 로비로 돌아간다 ([3.6](#36-방과-연결)).
  * LAN 1v1이라 NAT 통과·릴레이가 필요 없다. 인터넷 매칭은 만들지 않는다.

### 패킷 [가안]

| 패킷 | 보냄 → 받음 | 주요 내용 |
| --- | --- | --- |
| `MATCH_START` | 호스트 → 둘 다 | 역할, 이닝 수, 공격 횟수 |
